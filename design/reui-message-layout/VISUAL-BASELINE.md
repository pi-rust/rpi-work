两张图都是有背景、裁切、渐变或放大卡片的宣传素材，不是同窗口、同内容、同缩放的完整应用截图。它们适合核对层次和关系，不能直接把图像像素换成 CSS px，也不能与原型整窗截图直接做像素差分并宣称 1:1。

## 原型截图条件

- 视口：**1440 × 940 CSS px**；设备像素比 **1**；无额外缩放。
- 浏览器：Playwright Chromium；本轮采集版本 **156.0.8078.4**。后续实际版本及平台写入截图元数据。
- 每组使用新浏览器上下文，默认本地存储为空，不沿用用户偏好。
- 基础外观：浅色、阅读布局、16px 正文、舒适密度；额外采集深色及经典布局。
- 默认保留项目导航和右侧项目浏览器，等待离线「项目概览」标题可见并移开鼠标后采集；不为截图强制刷新页面。
- 从 `?view=new` 开始，输入 **整理消息区的视觉层次**；通过可控时钟检查 700ms 执行中和 1800ms 完成状态，不调用节点或模型。
- 正文与输入框共用既有阅读列；本轮不更改标题栏、侧栏、导航或右侧面板宽度。
- 基础工况下正文阅读列左边界为 **351px**、宽 **518px**。这些是当前原型的测量值，不是从宣传图推导出的目标值。

可重复采集：

```sh
mkdir -p /tmp/rpi-ui-visual-baseline
RPI_WORKBENCH_SHOTS=/tmp/rpi-ui-visual-baseline node design/reui-message-layout/verify.cjs
```

输出包括 `turn-running-light.png`、`turn-complete-light.png`、深色/经典布局、已展开执行过程及失败状态。`turn-hierarchy-metrics.json` 记录浏览器、平台、视口、DPR、主题、布局、密度、计算字体和正文/阅读列几何。输出目录是生成物，不作为仓库内持久的目标截图。

## 预览空白误判的核查结论

此前「深色切换后预览主体空白」的整窗目检结论被原始 PNG 证据推翻：原有浅色、深色和 HTTP 检查截图的标题区域都有 **2083 个深色像素**，裁切原图后主体、代码块和文件列表均完整存在。不能再把这条目检记录当作已复现的浏览器重绘缺陷；本轮未加入自动刷新、注入样式或修改 iframe 隔离的所谓修复。

新增 `verify-preview-pixels.cjs` 用原始整窗 PNG 而非元素截图检查实际像素：

- 在 DOM 测得的标题/主体区域统计 RGB 三通道均小于 180 的像素，标题须大于 100、主体须大于 500，拒绝空白图。
- 同一浏览器上下文内，与浅色初态比较，保留至少 90% 且不超过 110% 的文字像素，允许少量抗锯齿和光标差异；不跨平台硬编码像素数量。
- 本机概览页在普通/可控时钟、仅弹窗往返、浅/深色切换及系统主题跟随下，标题均为 **2083**、主体均为 **8811**。
- 在预览表单填写未保存文本并设置选区，切换主题后验证文本、选区和文档标记不变；`sandbox="allow-scripts"` 与不透明源保持不变。
- 设置 `RPI_WORKBENCH_SHOTS` 时保存整窗原图、从该图裁出的主体和 `preview-paint-metrics.json`。检查不强制滚动、刷新或修补页面以制造正常图像。

这些是当前浏览器和离线文档的像素完整性证据，不是所有平台均无绘制问题的承诺，也不等于与 Codex 的像素一致性验收。

## 本轮差异与验收

1. **完成回答仍嵌在执行过程里**：原来 `.turn-response` 的左边界为 371px，比阅读列缩进 20px；现将正文移为轮次的直接子元素，基础工况下回到 351px，并随窗口尺寸共享阅读列宽度。
2. **完成步骤抢占正文层次**：已完成步骤默认收进原生 `details/summary` 摘要；最终回答保持可见。执行中、失败和重试入口不被默认折叠。
3. **不以视觉精简牺牲交互**：读者已经展开的工具记录在完成及后台完成后保持可查看；手动收起的完成摘要在切换会话后保持收起。计划完成后的「开始实施」按钮位于摘要外，不被隐藏。
4. **验证边界**：在 1440/1280/1024px 桌面宽度、明暗主题、阅读/经典布局下检查正文几何及键盘展开；这些检查不等于原生应用像素一致。

## 正文密度校准

已复现同一页面的两条正文样式路径不一致：已有回答跟随阅读密度，而新完成回答固定为 `1.85`。现统一为既有桌面正文的舒适 `1.65` / 紧凑 `1.55`，不改变代码和工具日志的独立字号/行距。

| 字号 / 密度 | 原有回答 | 修正前的新回答 | 修正后的新回答 |
| --- | --- | --- | --- |
| 16px / 舒适 | 26.4px | 29.6px | 26.4px |
| 16px / 紧凑 | 24.8px | 29.6px | 24.8px |
| 18px / 舒适 | 29.7px | 33.3px | 29.7px |
| 18px / 紧凑 | 27.9px | 33.3px | 27.9px |

密度切换还暴露了可见标题约 10px 的上移。字号、密度和布局现在共用既有的块锚点保护：上翻时保留可见块的位置，原在底部时继续贴底；不重建消息 DOM，不跨刷新保存展开状态。这是块级锚点，不承诺字号变化后仍对齐到同一文字字符。

`verify-typography.cjs` 检查16种字号/密度/布局/主题组合、阅读锚点和底部跟随、草稿与展开状态、设置持久化，以及1440/1280/1024px桌面宽度。长中文正文、无空格路径和超长代码行仅作为测试内临时压力内容，随后恢复，不新增演示生成器功能或历史协议字段。正文保持换行，代码只在自身区域横向滚动。

截图输出包含 `typography-*.png` 和 `typography-metrics.json`；后者记录组合行距、代码/日志字体、块锚点位置和底部间距。它们验证内部排版一致性，不代表从宣传图推算出了目标应用的精确行距。

## Diff 横向阅读校准

长行压力检查复现：514px 宽的差异视口位于 x=910–1424，但反馈按钮原本在 x=4250，必须横向滚到行尾才可操作。现在所有行共用代码轨道宽度，两列行号固定在左侧，反馈入口固定在右侧；上述工况下按钮位于 x=1402–1424。上下文、增加、删除行分别保留各自的不透明底色，避免横向滚动的代码透过固定列。

行内反馈和审阅发现仍按可见视口宽度换行，不随超长代码轨道扩张。带空格的长文件名原先将38px标题栏撑到144px，现在保持单行省略，同时保留原有完整路径提示和打开源码动作。不增加审阅功能、后端状态或协议字段。

`verify-diff.cjs` 检查横向起点/中间/末尾的所有行号和反馈按钮、实际可见中心点的点击命中、鼠标悬停与键盘开关、上下文行83/新增行84/删除旧行84的反馈位置、未发送草稿、长反馈和发现、明暗主题、1440/1280/1024px桌面宽度及320px最窄面板。纵向被裁切行不会拿屏幕外中心点做伪点击断言；另滚动至底部检查末尾可见行。

截图为 `diff-sticky-*.png`，几何记录为 `diff-reading-metrics.json`。长行、带空格长文件名和长反馈均为测试压力内容，不把它们扩建为原型运行流程。

## 下一次严格对照还需要什么

- 同一目标应用版本、主题、字体、缩放/DPR和窗口客户区尺寸。
- 相同消息内容、执行阶段、面板开关与宽度、滚动位置。
- 未裁切且无宣传渐变叠层的目标应用截图。
- 在上述条件一致后，分别对照外壳、正文、执行摘要、代码/diff 与设置；不要用 TUI 源码或结构测试替代桌面截图证据。
