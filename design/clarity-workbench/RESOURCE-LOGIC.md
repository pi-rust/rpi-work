# 资源中心逻辑约束

> 本文先于视觉设计。原型数据不得把这些状态合并成一个“已安装”字段；生产页面必须复用节点与会话的真实观测。

## 一、资源类型不是安装状态

### Package

版本化的资源包，可包含：

- 主 Package 身份
- `SKILL.md` 及其 references/templates
- Tools 声明
- 持久提示词入口
- 可选的 Extension 设计声明

Package 通常是会话选择的主资源。一个 Package 已安装，不代表它已经被当前会话选择，也不代表节点实际加载成功。

### Skill

Package 内或节点目录中的 `SKILL.md` 资源。Skill 可以作为会话的精确引用，但以下状态必须分开：

- 本地内容是否已获取
- 节点是否已安装
- 当前会话是否已选择
- 会话是否实际加载

发现目录中的 Skill 仍然走“资源包目录”的获取/安装链路；不能因为类型叫 Skill 就绕过来源、摘要和授权检查。

### Extension

Extension 必须区分两种能力：

1. **Agent Extension**：节点执行侧的原生扩展，可能声明工具和权限；安装、更新、移除由节点管理器负责，会话还要单独选择并应用。
2. **UI Extension**：客户端侧的惰性 UI 贡献。UI 预览、显示偏好或已导入设计，不是 Agent 安装/加载证据。

`work-component-api` 的组件包是独立于原生 Extension 的安装链路，不放进原生资源列表中；尤其不能把远程协作组件和普通 Extension 共用一个安装状态。

## 二、必须分开的五个状态轴

| 状态轴 | 事实来源 | 能回答的问题 | 不能推断什么 |
|---|---|---|---|
| 本地内容 | `ResourceLibrary` 的 `acquired`、导入记录 | 客户端是否有可读设计/资源内容 | 不能证明节点已获取或安装 |
| 节点获取 | `PackageCatalog` 的 `acquired` | 节点是否拥有已校验的资源包字节 | 不等于安装、选择或加载 |
| 节点安装 | `NativeCatalog` 的 `facts.installed`、scope、回执 | 某项目/节点范围是否有安装记录 | 不等于当前会话已使用 |
| 会话期望 | `NativeConfiguration.desired` / `SessionBinding` | 当前会话或项目默认准备使用什么 | 不等于已应用或实际运行 |
| 实际加载 | `NativeSessionResources.actual`、readiness、operation | 节点是否实际应用并核验 | 缺失时必须显示“未核实”，不能推断成功 |

节点安装范围至少区分：

- `Project`：当前项目
- `Global`：节点全局

## 三、三种来源的真实操作链

### 当前节点

数据来自 `NodeApi::native_catalog`，是安装状态的权威来源。可操作：

- 查看详情 / 从节点检查
- 安装（仅当节点记录允许且来源已核对）
- 更新
- 重装
- 移除
- 刷新目录 / 回读

当前节点页不能显示本地设计数据来填补节点缺失状态。节点离线时显示上次记录或“未核实”，不能显示已安装。

### 发现资源

数据来自 `PackageCatalog`。每个发现项的流程必须按阶段推进：

1. 只读预览清单、来源、版本、文件数、大小和 SHA-256。
2. 可选“下载到本机”：只产生浏览器下载，不获取节点内容。
3. “获取到当前节点”：节点保存并校验资源包字节。
4. 获取回读成功后，才能显示“安装”入口。
5. 选择安装范围（当前项目 / 节点全局）。
6. 明确确认来源和授权后提交安装。
7. 安装回执成功后仍需刷新节点目录；不能直接把按钮变成“已安装”。
8. 会话选择和实际加载继续在会话资源设置中单独处理。

任何阶段失败或结果未知，都显示“请刷新核对”，不自动重试，不伪造成功。

### 本地设计

数据来自本地 `ResourceLibrary`，只表示设计内容和本地获取状态：

- 导入设计包
- 获取/保存本地内容
- 查看正文、来源和清单
- 导出 JSON
- 前往当前节点安装
- 查看当前会话引用

本地设计页不直接写节点安装状态；“已获取本地内容”不能显示为“节点已安装”。现有的 `node_installed` 旧字段不能作为新 UI 的权威事实，节点状态必须回到 `NativeCatalog` 回读。

## 四、会话边界

“用于本会话”不是安装操作，而是修改会话的 desired 配置：

1. 资源必须先有可解析的节点引用。
2. 主 Package、Skills、Agent Extensions 必须是节点管理器确认的已安装资源。
3. 用户在会话资源设置中选择固定版本/引用。
4. 会话空闲时提交 `NativeApply`，带 expected revision 和 operation ID。
5. 结果可能是 applying、blocked、applied 或 superseded。
6. 只有 `readiness == Verified` 且实际 observation 与保存 observation 匹配，才显示实际已加载。
7. 旧会话、未解析引用、节点离线或实际状态缺失，都不能显示“运行中/已生效”。

## 五、后续视觉设计规则

列表不是按资源类型复制三套卡片，而是按“当前任务和下一步操作”展示：

### 全局行结构

`身份 → 来源/版本 → 独立状态摘要 → 当前允许的下一步`

不显示重复的无意义更多菜单；操作放在详情或明确的行尾动作中。

### Package 行

优先展示：

- 固定版本和内容摘要
- 包含的 Skills / Tools / 提示词数量
- 节点安装范围
- 会话选择/实际加载摘要

### Skill 行

优先展示：

- `SKILL.md` 身份和来源 Package
- 本地内容、节点安装、会话选择三个状态
- 查看正文
- 只有已安装且可解析时才允许加入会话配置

### Extension 行

优先展示：

- Agent / UI 类型标记
- Agent 权限是“请求权限”还是“已授予/已核验”
- 节点安装和会话选择状态
- UI 贡献显示偏好独立于 Agent 状态
- 不把 UI 预览按钮写成安装成功

### 图标规则

图标只表达资源身份或明确状态，不为每一行强行放装饰图标；不使用每行重复的“更多”菜单图标。状态不能只依赖颜色，必须有文本或可访问名称。

## 六、远程发现目录的数据边界

远程目录可能来自 GitHub 或受控 API。它不是节点资源目录，也不是本地资源库；前端只能展示接口真实返回的字段。

### 允许直接展示的常见字段

- 名称
- 描述
- 来源仓库或来源地址
- 下载量 / 使用量（仅表示热度）
- 更新时间（仅表示源数据更新时间）
- 接口明确提供的版本、Release 或摘要

### 不得从远程目录推断或补造

- icon、作者头像或品牌图标
- 标签、Skills 数量、Tools 数量、依赖关系
- Agent / UI 类型
- 权限清单或已授予权限
- 节点已获取、节点已安装、会话已选择、实际已加载
- 下载量对应的安装量或活跃使用量

没有字段就隐藏对应区块，不用假图标、假标签、假数量或“默认值”填满卡片。资源类型可以使用当前路由/筛选器提供的纯文字标签，但不能伪装成资源自身声明。

### 只有元数据时的允许操作

如果接口只返回仓库地址、名称、描述、下载量和更新时间：

- 可以“查看来源”
- 可以打开 Release 或下载入口
- 可以获取一个候选文件并进入本地只读校验
- 不能直接显示“安装”或提交节点安装

只有候选内容通过 schema、manifest、路径约束和内容摘要校验，并且节点获取回读成功后，才进入“获取到节点”和“授权安装”步骤。GitHub 下载完成也不等于节点获取，更不等于安装。

### 远程列表的展示原则

发现目录应使用低信息密度的文本列表，而不是依赖装饰图标的资源卡：

`名称 + 描述 | 下载量 | 更新时间 | 来源 | 查看来源/查看详情`

版本、摘要、更新状态、安装范围和权限仅在接口或验证后的 manifest 确实提供时显示。列表行不展示节点安装、会话选择和实际加载状态；这些状态必须在当前节点或会话资源视图中回读。

## 七、原型验收边界

当前静态原型只能演示：

- 来源切换
- 状态组合
- 详情确认页
- 操作被允许/被阻止的原因
- 成功、失败、未知和回读状态的展示

原型不得伪造：

- 节点获取或安装成功
- 会话应用成功
- Agent 实际加载
- UI Extension 获得 Agent 权限
- 远程连接、扫码或真实授权

下一步先根据本文确认状态模型，再设计最终列表和详情页面；在确认前不继续修改生产 Dioxus，也不把当前静态列表截图视为最终方案。
