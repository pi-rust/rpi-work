# 单一对话与多文件审阅 · v0.3

日期：2026-10-23。根据讨论收敛：任务只保留 **对话 / 变更** 两个标签。本文替代早期独立执行记录、计划和工具页签的设计。

## 对话就是执行时间线

一条连续时间线依次展示：用户输入与附件 → Agent 说明 → 计划 → 工具调用 → 确认请求 → 结果与变更摘要 → 后续消息。

- 计划以内联可展开卡片展示进度和步骤。
- 工具调用卡默认展示动作、来源、状态和耗时，展开查看参数、输出和操作。
- 连续成功的读取/检索调用可折叠成一组；展开仍保留每次调用的结果。
- 失败、运行中、待确认单独展示；错误不能被成功调用的折叠组遮住。
- shell 命令及其日志位于对应调用卡内，授权卡紧随其后。
- 压缩摘要、子任务、取消、重试结果也属于同一时间线。
- Footer 的工具计数和右侧计划摘要只跳转到时间线中的对应事件。

原型保留工具配置弹窗，作为会话能力设置；它不是另一个执行记录页面。`/tools` 打开能力/权限设置，工具调用查看仍留在对话。

v0.6：工具、Skills、提示词配置统一从会话顶部进入，并支持组合为具名 Package。具体调用和载入证据仍位于对话中；详见 [会话资源与 Package](session-packages.md)。

真实实现中以 `eventId / runId / callId` 关联事件。流式输出更新已有调用卡，不创建大量重复消息；用户滚动阅读历史时，不强行滚回底部，应展示“新进展”入口。工具卡展开状态与滚动锚点由客户端持有。

## 文件多时，使用目录列表与单文件 diff

不为每个文件创建标签。桌面采用固定宽度的目录文件浏览区与自适应 diff 区；审阅时收起右侧会话上下文，把空间交给代码。文件列表与 diff 各自滚动。

原型提供 120 个本地样例，其中 3 个是本轮涉及的文件。支持：

- 文件名/完整路径搜索。
- 按目录分组、折叠/展开目录。
- 按修改、新增、删除、重命名筛选。
- 已审阅标记、仅看未审阅、进度计数。
- 上/下一个文件、下一个未审阅、文件列表上下方向键。
- 只看差异、文件路径、重命名来源、二进制占位。
- 针对文件提意见，回到同一对话并带上路径。
- 筛选无结果时明确提示并允许清除条件。

原型 DOM 包含 120 条文件元信息，每次仅生成当前选中文件的 diff。尚未实现列表虚拟滚动、服务端分页或真实按需 diff 请求。

手机使用「文件列表 → 单文件 diff → 返回列表」。文件选择后不把目录列表挤在代码旁边；返回时保留搜索、筛选和审阅状态。底部保留文件位置和下一项入口。

## 范围必须明确

两种范围是同一个变更浏览器里的筛选：

- **整个工作区**：当前节点项目中所有工作区变更。
- **本轮涉及**：本轮工具操作涉及的文件路径。

“本轮涉及”不是天然隔离的 Agent 专属 patch。原型显式展示审阅基准 `工作区 ↔ HEAD`；实际文件可能在 Agent 操作前就有用户修改。

如果要精确审阅本轮增量，必须增加轮次起始快照/基准，或 worktree 隔离。不能仅凭工具访问过的路径就把文件中的所有变更归给 Agent。

审阅标记表示阅读进度，不表示 Git 暂存、批准或提交。正式版用 `path + diffVersion/hash` 绑定标记；文件在审阅后变化，应自动恢复未审阅并提示。原型标记只在本次页面内存中保留。

## 更大规模的实现策略

| 规模或场景 | 实现方式 |
| --- | --- |
| 少量文件 | 同样使用文件列表，不再引入第二套横向标签 |
| 百级文件 | 先加载元信息，目录聚合计数，diff 按选中文件加载 |
| 千级文件 | 列表虚拟滚动、服务端搜索/分页，避免一次建立完整 DOM |
| 大 diff | 按 hunk/行块加载，折叠未修改段落，按需高亮，保留定位锚点 |
| 二进制/产物 | 按 MIME 提供预览或说明，不能生成伪造文本 diff |
| 文件持续变化 | 增量刷新状态与版本，旧请求返回时验证选中路径及版本 |

缓存键包含节点、项目、文件路径和 diff 基准/版本。切换文件可取消旧请求，旧响应不能覆盖新选择。不要预读所有文件正文；只读变更元信息的 API 与读取 diff 的 API 分开。

当前 rpi-web 已有 Git 状态和 diff 接口；分页、大 diff 分块与轮次基准属于需要新增或验证的能力。这里是框架约定，不代表原型已经实现生产端接口。

## 组件边界

`ConversationView` 统一组合 `InlinePlan`、`ToolCallCard`、`CommandOutput`、`ApprovalCard`、`CompactionEvent` 和消息/附件块。

`ChangeWorkspace` 组合 `ChangeFileBrowser`、`ChangeFilter`、`DiffPreview`、`ReviewProgress` 和移动端列表/详情状态。变更列表、选择和审阅进度不反过来改写会话原始事件。

## 验证

`scripts/verify-review.cjs` 验证两个任务标签、时间线内计划/命令输出、120 文件列表、路径搜索、空结果、类型筛选、重命名、二进制占位、本轮范围、审阅过滤、文件导航、键盘与手机列表/详情。

结果：`artifacts/review-validation.json`。桌面与手机截图均为浏览器实际渲染；120 个文件都是设计样例，未修改工作区源码。
