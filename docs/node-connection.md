# 节点连接交互

手机入口为“连接我的电脑”，默认展示相机扫码与相册扫码，也可展开“手动输入地址”，填写 HTTP(S) 节点地址与端口。识别二维码后核对目标地址再连接；手动输入后点击“连接电脑”或按回车连接。两种方式共用节点校验与密码认证，登录后加载项目和会话。手工表单默认收起，打开时关闭相机并取消未完成的图片识别，避免迟到的扫码结果覆盖输入；收起再展开保留当前草稿。

电脑设置保留“执行节点”：默认使用本机节点，可重连本机、连接其他节点，或通过“手机连接这台电脑”展示地址二维码。当前节点的在线、认证和能力信息均来自实际请求；界面不会将客户端所在电脑直接标成已启动或已在线。

Android始终使用手机模式；原生桌面始终使用电脑模式。Web结合移动设备标识与窄屏断点选择入口，手机横屏仍保持手机模式；从窄屏恢复到桌面布局会关闭相机并释放轨道。

二维码仍使用现有版本化地址协议，不包含密码；回环、通配地址、凭据与未知协议版本仍被拒绝。原生BarcodeDetector不可用时，以随应用分发的jsQR本地解码；相册识别不上传图片。

正式WASM复验：构建后运行 `node scripts/verify-device-flow.cjs`，覆盖桌面连接、分享二维码、手机识别后确认、真实二维码图片解码、延迟相机权限关闭和移动布局。相机权限使用测试流，不能代替真机摄像头验证。旧手机连接设计稿和原型截图属于历史设计，以本说明为准。

## 连接生命周期

连接与登录共用一条加载流程：健康检查 → 节点认证 → 协议能力 → 会话列表 → 项目列表。密码登录成功后直接加载工作空间，无须再次点击连接。任何一步失败都显示具体失败阶段，不把项目加载失败当成已就绪。整个尝试最多等待15秒，可以重试；切换节点或再次连接时取消前一次尝试，并以连接代数丢弃旧结果。编辑地址不会修改正在使用的节点，输入无效地址也不会清空当前工作空间。

成功连接后在本设备保存最多8个节点地址，最近使用的排在最前。重开应用尝试连接最近地址；认证已过期时再次要求密码。未认证、失败和超时的地址不会加入历史。记录不含密码或认证 Cookie；原生桌面保存在本机配置目录的 `rpi-work/nodes.json`，Web和Android使用本地WebView存储 `rpi-work-nodes-v1`。存储不可用时提示保存失败，连接仍可使用。

桌面设置可从“最近连接”切换节点或清除地址记录；清除不终止当前连接，但下次重开不再按该记录自动连接。手机保留扫码、手动输入和当前电脑的重新连接入口；手动编辑草稿不会改变当前连接，地址校验失败也不会清空已有工作空间。手机不会恢复桌面回环地址。相册选中同一张二维码可重复识别。

当前二维码仅用于传递节点地址，没有短时邀请、设备配对审批或设备权限列表。节点密码认证沿用rpi-http/rpi-web协议。本客户端不会假装启动本机服务；服务仍需由执行节点进程提供。

新增复验：`node scripts/verify-node-lifecycle.cjs`，覆盖真实浏览器Cookie登录、密码错误、自动重连、过期认证、地址校验、过期响应、项目加载失败、超时重试、清除记录与窄屏布局。与扫码脚本一起运行；服务端使用隔离HTTP测试节点，不触碰用户正在运行的节点。
