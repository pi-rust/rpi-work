## 1. 信息放在哪里

| 位置 | 常驻内容 | 点击后的详情 |
| --- | --- | --- |
| 对话 | 工具摘要、错误计数、图片/附件卡片、压缩记录 | 调用参数/结果、图片大图、文档摘要 |
| 对话中的工具卡 | 按执行顺序展示；成功调用可折叠分组 | 工具来源、参数、输出、耗时、权限、尝试次数 |
| 输入区上方（当前实现） | 待处理消息内联面板、数量与折叠入口；空队列隐藏 | 编辑恢复到主草稿、移除、空闲时立即发送；高级刷新／清空待执行／查看历史 |
| 输入框 | 图片/文档草稿、Provider、执行模式、思考强度 | 添加/粘贴/拖入附件、工具与权限、模型选择 |
| Footer（当前实现） | 供应商/模型/思考级别、会话累计输入/输出、缓存命中、费用、上下文 token/窗口与比例、已加载工具调用/失败数；速度与请求/重试仅在上报时显示 | 只读文本，无统计、上下文或工具弹窗入口 |
| 右侧上下文 | 当前上下文、自动压缩阈值、运行配置 | Provider 设置、压缩配置、队列 |
| 设置 → Providers | 节点连接配置与认证来源 | 配置地址、模型发现、模拟连接成功/限流 |

历史原型曾在手机 footer 只保留输入/输出、缓存和上下文，并把费用、速度、工具数放进可点击明细。**当前实现不再提供这种点击行为**：默认指标在窄屏紧凑换行，长模型 ID 等完整值直接在栏内换行，不省略、不使用 ellipsis，也不通过隐藏指标、悬停提示或弹窗补充明细。

### 当前实现：客户端底部状态栏插件

实现目录为 `apps/work-ui/src/features/observability/footer_plugins/`：`registry.rs` 是 typed、只读的内置注册表，`mod.rs` 提供 `FooterHost` / `FooterSettings`，`preferences.rs` 管理本地偏好。四个内置插件均为 v1，默认顺序如下：

| 插件 ID | 内容与 item ID |
| --- | --- |
| `session-identity` | 供应商/模型及可选思考级别：`identity` |
| `session-usage` | 会话累计输入/输出 `input-output`、缓存命中 `cache`、累计费用 `cost`；可选 `speed`、`requests-retries` |
| `context-usage` | 当前上下文 token / 窗口与比例：`context` |
| `tool-activity` | 已加载历史与当前投影中的工具调用数及失败数：`tools`，不是完整会话调用总数，也不是可用工具配置数量 |

「设置 → 底部状态栏」（通用页也有入口）可启停插件、逐项显示/隐藏、上移/下移插件及「恢复默认状态栏」；不支持 item 排序。全部关闭或没有可见项时不渲染 footer，不留空白占位，不影响草稿、模型或发送。

偏好保存在客户端 `localStorage` 的 `rpi-work-footer-v1`，schema 为 `version: 1`，`plugins` 必须包含上述四个 ID 各一次，数组顺序就是显示顺序；每项为 `{ id, enabled, hidden_items }`。默认全部启用且 `hidden_items: []`。读取默认值不写入存储；损坏、版本或列表无效时提示错误，临时调整只留内存，直到显式恢复默认才允许覆盖原记录。配额不足或写入失败同样保留内存设置并提示，不假装已持久化。

Footer 指标是普通只读 `span`，外层使用 `role="group"`，`aria-label` 包含完整标签、值与说明；内层 `.footer-value` 使用 `aria-hidden="true"` 避免屏幕阅读器重复朗读。没有 `title`、tooltip 属性或伪元素提示，也不新增 popup/Tooltip 组件。指标没有按钮、链接、键盘触发或点击/双击动作，点击或悬停均不打开统计、上下文、工具或模型弹窗，也不发运行时命令。`RuntimeDialogs` 可为兼容保留统计 modal 实现，但 footer 没有入口。字体沿用 UI 的 sans 字体并使用等宽数字（`tabular-nums`），默认桌面 12px、手机 11px（最小 11px），行间距 2px。正常字体、默认指标的移动布局高度不超过 80px；大字体、可选高级指标或长 ID 允许自然增高，不设硬裁切高度。此样式修正不改变注册表、偏好或计算口径。基础指标未知显示 `—`；明确上报的 0 正常显示。速度、请求/重试仅在节点明确上报时出现，否则缺席；请求/重试只有一项已知时，另一项显示 `—`。上下文必须有实际 token 与有效窗口才计算比例，不能从百分比反推 token，也不能在缺失上下文时推测百分比。未确认 scope 或断连时不沿用旧会话指标。

这是随客户端编译注册的内置 UI 插件，不加载任意外部运行时代码或注入 manifest，不在节点安装插件，不承诺 rpi `setFooter` API。资源库 Extension 的设计预览不因此成为可执行插件或正式运行时功能。

## 2. 工具调用

统一调用卡外观，按类型选择内容组件，而不是把所有结果都当成终端文本。

| 工具类别 | 关键输入 | 主要结果 | 操作 |
| --- | --- | --- | --- |
| read / grep / find | 路径、行范围、查询 | 文本片段、匹配位置、截断标记 | 展开、打开文件 |
| write / edit | 目标、修改范围 | 修改摘要、工作区 diff | 查看变更 |
| bash / powershell | 命令、目录、超时 | 分块日志、退出码、耗时 | 需要时单次确认、停止 |
| webfetch / websearch | URL、查询、数量限制 | 标题、来源、摘录、错误 | 查看来源、允许时重试 |
| MCP 工具 | 服务名、工具名、参数 | 文本/资源/结构化结果 | 展开资源、查看来源 |
| 子 Agent | 子任务、继承工具范围 | 进度、结果、错误 | 查看任务、取消 |
| 交互式浏览器 | 动作、目标、视口 | 截图/页面结果 | 能力存在才显示可执行动作 |

原型对话中包含上述八条具体调用记录，覆盖完成、失败、等待确认、运行中、已取消和不可用。

调用字段建议：`callId`、`sessionId`、`runId`、`source`、`toolName`、`arguments`、`status`、`startedAt`、`endedAt`、`permissionScope`、`outputBlocks`、`truncated`、`error`、`attempt`。调用 ID 用于归并增量和去重，不必在主界面常驻。

正式版重试应创建关联的新调用记录，保留旧错误；原型为了简化在原卡更新次数与结果。默认只为读/检索类失败提供重试，不把“重试 edit 或 shell”当作可无条件重复的操作。仅当宿主支持针对调用的取消时提供该按钮。

webfetch 与浏览器自动化分别呈现；未安装浏览器工具就显示不可用。日志执行中也保留工具卡，收尾后再固定最终耗时。

## 3. 消息队列

### 当前实现：主输入框与内联待处理面板

运行中在主输入框按 `Enter`，默认以 `followUp` 排队；`Shift + Enter` 换行，输入法组合确认不提交。停止按钮仍用于停止，不兼作排队按钮。收到服务端 acceptance 后才显示已排队，离线或拒绝时保留草稿。

「待处理消息」区域位于 `.composer-main` 内，与主输入框共用工作区宽度，不限制在较窄的正文阅读轴。非空时提供「收起队列／展开队列」，列表内部滚动，最大高度 `min(25dvh, 240px)`，手机条目操作至少 44×44px；无待处理消息时隐藏（错误、忙碌或历史展示除外）。不再使用队列弹窗、私有队列输入框或本地提案。

- **编辑**：请求 `cancel_queued`，只有节点明确给出取消成功结果后，才将条目原文恢复到主草稿；保留草稿已有内容及等待结果期间新输入的文字。失败、未找到或结果未知不冒充成功。这不是原子编辑，不自动重新排队。
- **移除**：仅取消指定待执行条目，不改主草稿、不发送消息。
- **立即发送**：仅空闲时可用，先确认取消成功，再提交原条目；不在运行中启动另一主任务。
- **状态边界**：服务端已领取或状态未知的条目不可编辑、移除或立即发送；用服务端快照校准，不猜测条目仍可取消。
- **高级操作**：「队列选项」收纳「刷新／清空待执行／查看历史」。没有暂停、排序或原子编辑承诺，也不把本地附件预览当作可发送附件。

后续消息由宿主在 Agent loop 即将停止时取走，不假定必须等待 `agent_settled`。宿主其他投递模式不改变主输入框默认 `followUp` 的简化交互。

### 历史 v0.2 原型（非当前能力）

历史 HTML 原型曾演示 `Alt + Enter`／队列按钮添加、引导与后续分类、独立编辑、上／下移、暂停／恢复、附件随本地草稿入队及「模拟处理下一条」。这些只操作本地演示数据，不驱动真实任务，不是当前客户端的功能承诺；当前行为以上节为准。

## 4. Provider 与模型

Provider 配置属于执行节点；模型和思考强度属于会话。用户切换会话模型不会改变上一轮的统计归属。

Provider 设置展示：配置名称、API 形式、base URL、凭据来源、模型发现、超时、重试策略和连接状态。连接检测分开报告网络、认证、模型可用性，不能把“服务可达”误报为“选定模型可推理”。

状态建议：`Unconfigured / Checking / Ready / AuthExpired / RateLimited / Unreachable / ModelUnavailable`。错误保留可读建议，认证失败不盲目重试，限流遵从服务器等待时间。

原型提供 DeepSeek、OpenAI 与自定义网关卡片；可模拟连接成功和 429。API Key 不是可输入字段，不记录真实凭据。

模型能力从宿主发现：支持的输入类型、工具、思考级别、上下文/输出上限。示例中的 High/Max/Off 不应成为所有模型的固定枚举；正式版按 `get_available_thinking_levels` 的结果展示。

## 5. 上下文压缩

历史原型中 Footer 显示占用比例，右侧显示估算 token 与模型窗口，点击可查看组成、自动压缩开关、阈值、保留要求、摘要预览。**当前实现**的只读 footer 不触发上下文管理；原生压缩仍从 inspector 的「查看任务上下文」→ 管理上下文入口（按钮「管理当前上下文」）打开「上下文与压缩」modal，不因插件化移除或迁移到 footer。

压缩状态：`Idle → Scheduled → Compacting → Completed / Failed / Cancelled`。先尊重宿主能力与互斥规则；运行中或待工具确认时，手动压缩按钮禁用。原型在空闲时直接生成预置摘要，没有模拟模型耗时。

一次压缩记录至少包含前后估算量、摘要、保留范围、最近消息策略、时间与结果。失败时保留原上下文，给出重试机会。

原型示例：`48.6k / 128k（38%）→ 12.4k / 128k（10%）`。这是固定示例，不代表真实模型压缩能力。系统/历史/工具/附件的分类同样为估算示意，现有 `ContextUsage` 没有提供这些分项时应隐藏分类。

**压缩改变下一次请求的上下文，不删除原始会话记录，不清空累计 token 与费用。** 自动阈值配置是否能在当前宿主动态修改，需要新增或验证；不能只改客户端开关就声称已经改变运行时策略。当前 `compact` 命令已有 `customInstructions` 参数，可对应保留要求。

## 6. Token、缓存与费用口径

每份统计应携带作用范围、提供方/模型、请求或轮次 ID、更新时间和来源：Provider 上报 / 宿主聚合 / 客户端估算。生成中的数字可标为暂估，结算后才固定。

### 统一口径

```text
输入总量 = 未缓存输入 + 缓存读取 + 缓存写入
总 Token = 输入总量 + 输出
缓存命中率 = 缓存读取 / 输入总量
会话命中率 = Σ缓存读取 / Σ输入总量
```

缓存写入属于输入总量，不能当作缓存命中。思考 token 若是输出的子集，就仅作为细分展示，不能再加到总量中。

本轮示例：未缓存 `8,000` + 缓存读 `24,000` + 缓存写 `0` = 输入 `32,000`；输出 `4,800` 已包含思考 `1,200`；总量 `36,800`，命中率 `75%`。

### 数据映射

本机 `rpi-ai::Usage.input` 是未缓存输入，其 `cache_read` 与 `cache_write` 单列；不能把它直接标成“输入总量”。`reasoning` 文档明确是 `output` 子集。

`rpi-cli/src/modes.rs` 的 `get_stats` 当前返回 `cachedTokens`、`uncachedTokens`、`totalTokens`、`costTotal`、`cacheHitRatio`、操作/重试/压缩次数；其中 `uncachedTokens` 已含 cache write。若已使用这份统计，就不要再次叠加 cache write。输入/输出分项、逐轮来源、速度/首 token 延迟等可能需要从 usage 事件和计时数据聚合，不能假设 get_stats 已全部返回。

上下文占用是当前请求构建后的估算，不是会话累计输入。累计输入会因为多次请求重复包含历史而增加，因此可以大于模型窗口。

### 费用与缺失值

- 费用优先采用提供方/宿主上报；根据模型费率推算时标“估”，保留费率版本、币种和来源。
- 缓存读写可有不同费率，不能简单用总 token 乘统一价格。
- 不同模型/提供方混用时保留每次请求归属；只对同币种金额聚合。
- `null / 未提供 → —`；只有明确上报 0 才显示 0。分母为 0 的命中率显示 —。
- 本轮与会话累计分开；缓存比例不采用各次百分比的算术平均。
- 生成速度与首 token 延迟须说明测量范围；不能把工具等待时间混进纯生成速度。

Footer 的 `↑ / ↓` 对应输入总量与输出；历史原型中的示例费用为虚构估算，不能用于预算或实际账单核对。当前 footer 明确显示会话累计值，费用取节点上报的累计 USD，非账单；不把本轮示例或本地计时当作实时统计。

## 7. 图片、附件与项目引用

三种对象分别处理：

1. **项目引用**：节点已有的授权目录内文件，用路径/行范围引用，不等同于上传本机附件。
2. **用户选择的附件**：来自桌面文件选择、拖拽或手机上传，先进入草稿。
3. **工具生成的产物**：属于调用结果，显示资源卡、预览与下载。

原型已实现前两种的交互；工具产物资源卡是后续扩展。

### 当前原型

- 添加示例图片、示例 Markdown；消息中显示缩略图/文件卡。
- 选择本地文件、向输入框拖文件、粘贴图片。
- PNG/JPEG/WebP 用本地 object URL 预览；图片可放大/缩小/适应窗口。
- 文本/代码以转义文本预览，最多读取前 12 KB；PDF 只展示文件元数据。
- 每条草稿最多 6 个附件，每个不超过 10 MB；不支持类型会被拒绝。
- 可移除草稿附件；发送或加入队列后保留预览引用。
- 仅浏览器本地处理，不上传、不持久化，不把内容发给模型。刷新重置会话与附件。

附件是用户主动选择时才读取；没有遍历项目目录或主动读取本机文件。内置 SVG 是受控设计参考图；用户上传 SVG 不作为可执行内容渲染。

### 需要补齐的传输协议

此次源码检查中，`modes.rs` 的 RPC prompt 路径主要提取字符串 `message`，queue 路径同样创建文本消息。即使底层有 `ImageContent`，也不能据此声称 Web/RPC 已支持图片上传。

建议在 rpi-web 增加节点附件对象：上传后返回 `attachmentId`、MIME、大小、SHA-256、解析状态；prompt/queue 使用附件 ID，节点验证归属与会话权限。手机路径不当作服务器路径。临时对象未发送即清理，已发送引用绑定会话生命周期。

生命周期：`Selected → Validating → Uploading → Ready → Attached`，也可能 `Rejected / Failed / Cancelled`。上传失败可单独重试/移除，消息不应悄悄忽略失败附件后发送。

图片必须按模型发现的视觉能力发送；不支持时明确提示，不假定换个 provider 名称就支持视觉。文档提取与 OCR 是额外能力，不能将 PDF 文件卡假报为已读取全文。附件转文本后显示实际纳入上下文的范围和估算量。

## 8. 快捷入口

原型支持 `/queue`、`/compact`、`/model`、`/provider`、`/tools`、`/stats`；按发送打开对应管理界面。实际版本可以按宿主命令能力生成命令菜单。

当前主输入框 `Enter` 空闲时发送、运行中默认按 `followUp` 入队，`Shift + Enter` 换行；停止按钮仍为停止。`Alt + Enter` 加队列属于历史原型交互，不作为当前承诺。保留中文输入法组合事件，图片粘贴只在消息输入框接管。

## 9. Dioxus 框架承接

在既定 `work-core / work-client / work-ui` 边界增加以下模型，而不新造 agent loop：

- `ToolCallProjection`：工具卡与输出块的增量投影。
- `QueueEntry`：宿主 entryId、交付模式、状态、附件引用；用快照校准。
- `UsageSnapshot`：scope、provider/model、source、nullable 指标、结算状态。
- `ContextSnapshot`：窗口、估算量、阈值、压缩记录；组成分类可选。
- `AttachmentDraft`：平台文件句柄/节点 ID、本地预览、上传与解析状态。
- `ProviderConnection`：节点配置引用、认证状态、动态模型能力。

避免把 token 统计写成 UI 字符长度计数。避免把桌面 `PathBuf` 作为 Web/WASM 附件通用模型；平台文件访问留在 platform adapter，节点 ID 才是服务端通信对象。
