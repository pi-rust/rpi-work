## 1. 产品定位

一个以 Rust 为核心的个人 Agent 工作台。用户在桌面发起复杂任务，在手机查看进展、补充指令和回应确认；项目文件、工具和模型凭据属于执行节点。

首个场景聚焦编程任务：**打开项目 → 交代目标 → 规划与执行 → 查看变更 → 验证与继续**。界面要让人知道 Agent 正在做什么、需要什么、已经交付什么。

“支持手机”首版定义为手机控制电脑或服务器上的同一会话。手机本地执行完整工具链、离线推理和任意操作系统操作不纳入首版。

## 2. 产品对象

| 对象 | 用户理解 | 技术边界 |
| --- | --- | --- |
| 工作空间 | 我的项目和任务入口 | 首版单用户，可连接一个执行节点 |
| 执行节点 | 真正处理任务的电脑/服务器 | 拥有文件、凭据、进程、会话存储 |
| 项目 | 一个已授权的工作目录 | 路径位于所选节点，手机无法直接打开电脑任意路径 |
| 会话/任务 | 围绕一个目标的持续工作 | 首版一个任务对应一个 rpi 会话；运行轮次属于会话 |
| 运行轮次 | 发出一次指令后发生的工作 | 接受指令、工具调用、等待确认、最终结算 |
| 模型 | Agent 调用的推理服务 | DeepSeek / OpenAI 等，由 rpi provider 提供 |
| 运行时 | 驱动工具、历史和执行生命周期的系统 | 首版 rpi；Codex app-server 是后续独立适配 |
| 扩展 | 为 Agent 增加能力的包 | 运行在节点，由 rpi 宿主管理 |

## 3. 信息架构

桌面：左侧项目/会话，中间任务区，右侧上下文。顶部始终能辨认当前项目和执行位置。

- 工作空间：项目、会话、搜索、新建任务。
- 任务区：对话、变更；工具执行记录、计划与确认都嵌在同一对话时间线。
- 上下文：执行节点、模型、权限、进度、文件、扩展。
- 扩展：查看可用能力、会话启用情况与兼容信息。
- 执行节点：当前节点、远程节点地址、设备授权入口。
- 设置：外观、连接、模型配置入口。敏感凭据留在节点端管理。

手机：同一会话模型，主对话单栏；项目列表和上下文使用抽屉；diff 使用单列；执行确认必须完整显示命令、路径和作用范围。文本输入保留中文输入法组合状态，不将候选确认误当成发送。

## 4. 功能优先级与已有基础

“已有”表示在相邻仓库中观察到实现，不代表已经接入本原型。

| 功能 | 首版要求 | 基础与新增工作 |
| --- | --- | --- |
| 项目/会话 | 新建、打开、搜索、改名、恢复历史 | rpi-web 已有项目与会话 API；新客户端接入 |
| 流式对话 | 文本、工具调用、耗时、错误、取消 | 已有 RPC → HTTP/SSE；Dioxus 重建组件与 reducer |
| 长任务状态 | 区分处理中、等待确认、失败、中断、完成 | 使用 `agent_settled` 最终结果，不能用文本停止判断完成 |
| 运行中补充指令 | 显示队列、取消未处理消息 | 已有 queue 命令；UI 接入并解释 steering 与 follow-up 能力 |
| 文件与 diff | 只读文件预览、工作区 Git diff | 已有 API；Dioxus 重建预览与代码高亮 |
| 命令确认 | 待确认、允许一次、拒绝、失效 | 复用宿主权限/dialog 协议，核对扩展真实支持的动作 |
| 模型与工具 | 展示宿主可用模型，选择思考级别和活动工具 | 已有 discovery/command；不硬编码模型名和权限范围 |
| 手机接续 | 同一节点、同一会话、刷新与重连恢复 | 响应式 UI + snapshot/SSE；需要真实弱网测试 |
| 桌面集成 | 打开目录、窗口、节点服务启动/停止 | Dioxus 桌面平台适配与进程监管新增 |
| 扩展配置 | 展示实际加载情况、能力边界 | 仓库已有扩展；管理 API、可信安装和兼容检查需新增 |
| 计划与 todo | 对话中的内联进度卡，可展开步骤 | 已有相关扩展；稳定结构化投影需验证，不假定已有统一计划 API |
| 设备配对 | 可撤销、短时凭据、逐设备授权 | **新增**，当前 rpi-web 为共享访问密码模式 |
| 原生手机包 | Android/iOS 壳、键盘与深链等 | 第二阶段 Dioxus 验证；首版先 Web |

## 5. 三条核心流程

### 桌面开始工作

选择本地节点 → 打开项目 → 新建会话 → 选择模型和权限 → 发出任务 → 观察工具进度 → 审阅工作区 diff → 继续或结束。

首版“执行记录”是已有工具日志的只读视图。交互式终端/PTY、任意 shell 输入另行实现。

### 手机接续

节点已经运行 → 在受保护地址打开工作台 → 登录 → 选择同一会话 → 获取 snapshot 与事件游标 → 继续接收事件 → 发补充消息/停止/回应确认。切出浏览器后回来必须重新同步；不依赖后台页面持续在线。

### 执行确认

宿主产生确认请求 → 界面显示请求 ID 对应的动作、参数、路径、影响 → 用户允许一次或拒绝 → 节点校验请求仍然有效 → 广播关闭事件 → 所有客户端更新。两端同时回应时，后到的一端显示“已由另一设备处理”。

“允许”只代表权限决策，不代表命令成功。成功必须来自随后工具执行结果和最终结算。原型为了演示将这两步合并，真实实现必须分开。

## 6. 状态与失败体验

| 状态 | 用户看到什么 | 可做什么 |
| --- | --- | --- |
| Ready | 会话可用 | 发送指令、切换模型 |
| Running | 流式进度与工具耗时 | 停止、补充消息 |
| AwaitingInput | 明确的请求内容 | 回应或拒绝 |
| Cancelling | 正在中断 | 等待宿主确认，不能立刻假报停止 |
| Settled(completed) | 完成与验证结果 | 审阅、继续 |
| Settled(failed) | 可读错误与已保留成果 | 修正配置后重试 |
| Settled(interrupted) | 中断原因及恢复入口 | 由宿主恢复，不能自动重放工具副作用 |
| ConnectionLost | 显示连接中断与上次同步时间 | 重连，状态未知时不盲目重发命令 |

连接状态独立于任务状态。SSE 断开不能表示任务失败；桌面关闭后是否继续，取决于执行服务是否仍在后台运行。

## 7. 原型使用说明

入口：`design/prototype/index.html`。

- 默认任务停在待确认状态，可以允许或拒绝；从任务菜单重置演示。
- 只切换对话/变更；对话内展开计划、工具和命令输出。变更页可搜索 120 个文件样例、按目录/类型/未审阅筛选，点击文件打开单文件 diff。
- 可发送模拟消息、停止模拟回复、切换规划/执行、选择模型、添加上下文引用。
- 新建任务和搜索可用；任务仅保留在本次页面内存。
- 扩展开关仅改变示例配置；设备配对仅展示流程，不发送请求。
- 设置支持浅色、深色、跟随系统；主题偏好保存在浏览器。
- 顶部手机预览可体验窄屏；真实窄视口还包含触控尺寸和输入适配。

原型没有实现 PWA manifest、service worker、通知或网络离线同步；不能把“能在手机浏览器打开”当作已经完成 PWA。

## 8. 分阶段交付

整体视觉通过 [主题系统](themes.md) 配置：主题风格、明暗与密度分开选择，顶部入口实时预览、确认保存，支持主题 JSON 交换。主题覆盖桌面和手机的所有业务区域。

流式消息的状态、顺序、停止确认、连接恢复、滚动和统计口径见 [流式消息与运行状态](streaming.md)。HTML 原型已支持本地模拟事件；未接入真实模型或 SSE。

1. **设计确认**：选择核心用户场景、Dioxus vs React 复用、手机形态。当前交付在本阶段。
2. **技术验证**：Dioxus Windows + Web 两个目标连接相同 rpi-web，验证 SSE/鉴权/长对话/diff/中文输入。通过后冻结架构。
3. **纵向 MVP**：一个节点、真实项目、一个可恢复会话、一个 provider、文件/diff、停止、确认闭环。
4. **产品化**：多项目、后台服务、模型与扩展设置、可撤销设备授权、PWA 安装体验。
5. **移动与扩展**：Android/iOS、远程节点、多运行时、通知、worktree、子 Agent 等，按实际使用需求推进。

## 9. 一起讨论的三个取舍

1. 是“以编程为首场景的个人工作台”，还是第一天就覆盖浏览器/文档/日常操作？建议先编程，扩展承接其他领域。
2. 是“端到端 Rust 的长期方向”，还是“最快发布且复用现有 UI”？前者优先 Dioxus 验证，后者优先 Tauri + React。
3. 手机首版是 Web 接续还是必须发布原生包？建议先把同会话跨端闭环做稳定。
