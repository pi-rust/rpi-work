# rpi 会话资源配置：最小契约提案

> **正式实现入口：**当前 NodeApi、原生资源页、精确会话与持久化源码开发见[原生资源与源码开发指南](../guides/native-resource-authoring.md)。下文保留设计时的提案与缺口记录，不代表当前支持状态；不得据此猜测命令。

> **状态：实施前提案，不是已有 API，也不是本轮业务代码交付。**基于[产品共识](头脑风暴文档.md)及[真实能力验证](../reviews/rpi-session-resource-validation.md)。本文给出所需语义和推荐分工；操作名、字段名只是讨论用名称，不可当作可调用的 rpi 命令。
>
> 首版仍是“一个主 Package + 多个 Skills + 多个 Tools”，默认基础 Package、可立即输入、空闲修改、同项目并发独立、保留历史。不增加长期 Agent 对象，不另造包格式，不建设前端资源版本升级系统；ACP 资源定制与远程资源分发不在此契约内。

## 1. 从用户动作约束接口

| 用户动作 | 必须成立的事实 | 当前已具备 / 缺口 |
| --- | --- | --- |
| 新建会话后直接输入 | 默认配置在首个模型请求前就绪；无需向导 | 普通会话已有；定制资源启动参数和确认待补 |
| 打开资源面板 | 看到本会话选择与宿主实际状态，未知有明确标识 | Tools 有部分 RPC；Skills/来源清单缺失 |
| 修改主 Package/Skills/Tools | 只改本会话；下一轮使用已确认的新配置 | 工具切换可用；精确资源选集和整体应用待补 |
| 暂时关闭工具 | 实际模型工具集合符合选择，不因空选反而扩大 | `set_active_tools([])` 当前表示全部，不能映射为“全部关闭” |
| 重开旧会话 | 历史继续；有已保存资源选择时先恢复配置再执行 | 历史恢复可用；配置恢复待补 |
| 安装一个独立工具扩展 | 本机全局或项目可获取，再由会话选择 | 项目原生安装/组合已验证；生产安装流程待补 |
| 安装后返回旧会话 | 如实显示是否已加载，不声称自动生效 | 当前 RPC 宿主不自动发现新增 Skill |

### 硬性边界

- 不轮流覆盖项目共享 `.rpi/settings.json`；不复制项目制造“隔离”；不重写 transcript。
- 资源选择不控制插件代码所有副作用。原生库加载、注册、钩子可能执行代码；工具未暴露给模型也不等于扩展被卸载或被沙箱限制。
- Package 的附带资源必须由原生机制解析，不能假设 `package link` 已分发 Skills/Prompts/Themes。
- 本机“全局安装”是资源作用域，不等于全部会话自动启用，也不等于安装到所有设备。

## 2. 最小数据边界

**只需要会话选择、一次应用记录和宿主观测三类数据**，不先建 AgentProfile、部署中心或独立工作流引擎。

### 2.1 会话选择（节点持久化）

| 内容 | 语义 |
| --- | --- |
| SessionKey | `NodeId + SessionId`，校验所属 ProjectKey；不按显示名称定位 |
| 配置 revision | 本节点对该会话配置的单调修订号；不是 Package 版本，不是用户确认升级流程 |
| 主 Package 引用 | 恰好一个；默认基础能力引用，不为此虚构一个已安装的原生包 |
| Skills 选择 | 精确的所选资源引用；包内项及独立项同样需要可追溯来源；空选与默认选项不同 |
| 工具提供来源 | 主 Package 与所选独立扩展映射出的原生提供者；不把每个工具重复安装为一个包 |
| Tools 选择 | 显式 `default` / `only(names)` / `none`，不得复用空数组的歧义 |
| 补充指令 | 本会话指令，不改共享 Package；模板仅进入草稿，不是已注入指令 |

引用优先沿用 rpi 的安装记录和资源身份；不足时由节点生成不透明引用，解析到经授权的原生来源，不新造可执行 manifest。工具名只有在本次注册表和来源诊断下才有含义；同名 Skills 的来源不能靠名字猜测。

客户端不提交任意 DLL 路径、argv、可执行文件或环境变量。节点负责解析安装范围、可信来源及宿主兼容性；凭据不进入会话资源记录、确认指纹或前端快照。路径存在也不能证明内容未变。

**配置 revision 不固定资源发布版本**：实际加载版本/内容由宿主报告；原生目录内容变化时旧观测失效并重新核对。缺失已选资源应报错，不静默替换为另一项；不承诺自行追踪下载或后台升级。

### 2.2 宿主资源观测（事实，不由前端推导）

一次完整观测至少包含：会话身份、宿主代次、对应配置 revision、实际提供者/资源来源、已加载 Skills、已注册工具、模型有效工具集合、Skills 模型可见性及诊断。无法可靠返回的字段标未知，不填默认成功。

- **已安装**：节点目录事实，不是会话加载事实。
- **已加载/注册**：宿主已经发现/载入；扩展加载与工具注册分别表达。
- **对模型有效**：下一轮实际可见集合；不是简单照抄 `activeTools`。
- **本轮使用**：关联既有工具执行或文件读取证据；列表出现不表示已使用，读取文件也不证明模型遵守指令。

特别约束：0.15.0 实测 `activeTools=[]` 时模型收到全部六个已注册工具，而 Skills 列表又受到 `read` 显式选择门控。因此需要返回实际展开后的集合及可见原因，不能按选择数组长度计算“启用 0 项”。

宿主代次用于区分相同 session ID 的旧/新进程。代次变化或断连后，旧 applied 记录只作历史，不再授权新执行。沿用现有事件订阅/失效通知与快照重读即可，不新增平行事件日志。

### 2.3 一次应用记录（节点持久化）

记录操作 ID、会话、基础 revision、目标选择、进行状态、已验证 revision/宿主代次和错误。它支持重复请求查询及崩溃恢复，不等于实现完整安装事务系统。

同一个操作 ID + 相同内容返回既有结果；相同 ID + 不同内容报冲突。记录不可读时停止变更并报错，不能以空配置覆盖损坏文件。

## 3. 四个操作语义【均为提案】

这些是服务职责，不预设 HTTP URL、RPC type 或需要新增四套传输。

### A. 获取资源能力与快照

沿用运行时能力协商，分别标明：工具选择、精确 Skills/提供者选择、资源观测、原进程重载、同 ID 重开。能力不存在就不展示可执行入口；仅支持工具选择不能宣告支持整个资源面板。

复用 `get_available_tools` / `get_state` 可返回已有事实；在宿主补齐资源快照前，不能把磁盘扫描伪装成加载清单。旧扩展能力结构可增补或组合，不另建同义资源管理体系。

### B. 创建带资源选择的会话

新建时使用默认基础配置；用户提前选择时可携带目标配置。节点先记录选择，再启动宿主、核对观测，最后开放执行。初始化与用户提交可以在同一流程完成，不要求用户操作向导，也不能先按更宽默认工具发出第一轮再后台应用。

现有无定制的旧会话保持 legacy 行为，不因为新记录尚不存在就被静默迁移；明确启用定制后才适用对应恢复门槛。当前普通基础会话能创建，不等于精确主 Package 选择已经实现。

### C. 空闲应用会话选择

输入：SessionKey、期望基础 revision、操作 ID、完整目标选择。返回：明确拒绝、已接受但未完成，或带观测的已完成结果；接收不等于生效。

节点需要原子地检查并占用会话配置/执行门：

```text
核对 revision、能力及信任 → 确认空闲并占用门
  → 持久化目标操作 → 应用到宿主 → 读取实际快照并比对
  → 持久化已验证配置/结果 → 开放后续执行
```

- 空闲包括：没有运行、等待授权/Ask、压缩、恢复、未结算取消或其他变更；新 prompt、resume、队列自动消费必须经过同一个门。
- UI 禁用仅是体验；节点必须拒绝忙碌和过期 revision。两个客户端竞争时只有一个被接受，另一个重读，不自动覆盖。
- 检查信任和文件解析可以在载入前进行；试加载原生代码**不是无副作用的预览**，仍需此前已确认的安装/加载信任边界。
- 只要无法证明实际集合与目标一致，就不标记完整 applied。权限策略排除所选工具时显示具体诊断；不能静默修改目标或扩大到默认工具集。
- 应用耗时超限/连接中断时标未知，保留操作 ID 查询和重读；不自动再次加载、重新安装或发送模型请求。

### D. 重开与恢复

同 ID 重新打开时，节点识别新宿主代次，读取会话选择，应用并核对后才允许任何可能触发执行的入口。旧历史保持原状；已进入上下文的旧指令和工具结果不会被消除。

如果崩溃发生在“宿主已应用、节点未落盘”之间，恢复时先处理未完成操作并重新观测，不根据旧成功记录直接放行。历史能读不等于资源已恢复。恢复失败保留可查看的会话与历史，执行门保持关闭，允许用户修复资源或明确改选。

## 4. 两条应用路径与推荐顺序

### 第一小步：已注册工具的非空选择

复用 `set_active_tools`，在节点统一处理忙碌校验、注册表名称校验、保存及重开前重应用。上游当前可能接受未知工具名，Work 不应拿无效占位名称模拟“禁用全部”。

在零工具语义补齐前：请求 `none` 返回明确 Unsupported；UI 不显示“全部关闭成功”。`default` 若会展开为全工具，必须显示真实有效集合。独立一次工具配置成功只能报告该范围成功，不宣告 Package/Skills 整体应用。

### 完整资源配置：优先复用宿主库层重载，保留受控重启方案

| 路径 | 复用点 | 尚需补齐 | 限制 |
| --- | --- | --- | --- |
| 原进程重载 | 原生资源解析、`set_resources`、`set_tools`、`set_system_prompt`、CLI reload 例程 | 每会话精确选择、受支持 RPC、实际清单、忙碌门、失败一致性 | 不能把多个 setter 的先后调用假装成原子应用；中间失败应停止执行 |
| 同 ID 受控重启 | extcore Host 生命周期、session reopen、原生启动参数 | 每会话参数透传、精确选集、重应用确认、失败恢复 | 不能让旧/新进程同时写同一历史；原生内存状态会重置；仍不消除旧上下文 |

**建议先补共同的精确选择、观测与恢复契约，再决定主路径。**重启已证明可续用历史，但 additive `--skill` 与 `--local-only` 本身不能完成完整资源选择，不能将“先重启”当作绕过上游缺口的捷径。

失败时优先保持停止/未知并提示修复。只有重新核实旧配置和资源仍有效后才能恢复旧配置执行；不承诺回滚原生代码副作用，不重新运行旧工具。配置应用不顺带卸载共享资源，不影响其他会话。

## 5. 分工与最小实施批次

| 批次 | 交付位置和复用点 | 完成标准 |
| --- | --- | --- |
| 0：语义与协议对齐 | rpi 上游：明确 `default/only/none`、精确选集、资源快照、应用模式；确认 extcore 发布版本 | 有测试与真实 ready/响应；协议名确定前不在 Work 填假命令 |
| 1：工具配置窄闭环 | Work 现有 `work-core` 契约、`LocalWorkspace` / runtime adapter、会话资源 UI；extcore 需要时补入口 | 非空选择可保存与恢复；空选明确拒绝或经上游支持；竞争/忙碌/断连不伪成功 |
| 2：完整会话资源 | 上游原生加载器与 extcore `SessionOptions`/Service 配置透传；Work 节点记录与现有客户端 | 默认主 Package、新建选择、精确 Skills/Tools、空闲应用、实际清单、同项目并发隔离 |
| 3：本机安装闭环 | 现有原生 registry/install/link；Work 资源库和节点适配 | 全局/项目范围真实安装，附带资源分发、来源风险确认及失败恢复；已安装与已加载分离 |

这些批次是实施建议，不是确认可以直接改相邻仓库。上游改动应单独评审/发布；Work 使用确定发布的版本，不能依赖机器上的相邻源码。暂不抽新 crate，不更换本机传输，不强制本机请求绕 HTTP。

`work-core` 放契约/校验，节点服务拥有记录与执行门，`work-client` 复用现有 transport/Session 访问，UI 只编辑与展示。现有 desired extension pins 不自动变成原生资源授权；旧设计 JSON 仍是 inert 数据。资源安装与运行时配置分开，不能让导入文件自行决定执行命令。

## 6. 验收矩阵【未来实现必须补测】

既有脚本只能证明已有底层行为，不能替代以下新契约验收：

1. 同项目 A/B 各自选择不同主 Package/Skills/独立扩展；同时执行，模型真实收到各自精确集合，无未选资源混入。
2. 默认基础会话无向导，第一轮执行前完成初始化；不产生按默认宽工具集抢跑的请求。
3. `only`、`default`、`none` 分别验证模型请求工具 schema；空选不得等于全部。未知工具名拒绝；策略收窄可诊断。
4. 运行/Ask/压缩/取消未结算时拒绝应用；应用中到达的新输入和队列不能抢跑；重复操作不重启两次。
5. revision 冲突返回最新事实；相同 session ID 的旧宿主事件不覆盖新代次；断连不沿用旧 applied 许可。
6. 重启、节点崩溃、配置写入失败、资源缺失、ABI 不符、重载部分失败均不能静默扩大工具；未完成操作可查，不重放模型/工具副作用。
7. 更换资源后历史及旧工具结果继续存在；卸载/停用不承诺清除旧上下文；同一 transcript 始终只有一个 writer。
8. Skill 已加载但无 `read` 时准确显示不可见原因；重新启用后恢复可见；“本轮使用”必须有独立证据。
9. 安装完整 Package 时真实分发其非 DLL 资源；只下载/导入/安装都不能冒充会话已加载。升级仅反映宿主事实，不新增前端版本审批系统。
10. 老宿主、旧会话及 ACP 不支持时明确降级；不误广告完整资源配置，也不篡改旧 desired pins。

## 7. 仍需决定的事项

- 上游正式操作/能力名称与快照字段，以其实现及兼容性评审为准；本文不要求同名 API。
- 完整配置主路径选原进程重载还是受控重启；需要考虑扩展内存状态与错误恢复，不仅是历史能否打开。
- 默认基础 Package 的真实资源内容与来源，不能为了消除技术缺口而假设一个现成发行包。

在这些事项明确前，可以按真实能力继续使用当前 Tools 入口；完整 Package/Skills 选择应显示未接通，而不是先实现乐观成功的前端状态。
