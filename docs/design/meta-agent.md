# 元Agent · 个人能力开发项目

> 截图与运行报告为本地产物，不随Git分发；文中路径用于定位本地文件。保留规则与复验入口见 [测试产物说明](../guides/testing-artifacts.md)。

元Agent 是添加项目时可选的一种项目类型，面向个人编写、试用和复用自己的 Agent 能力。与普通项目共用对话、文件预览、变更、用量和追踪；名称统一为「元Agent」。此阶段没有团队协作、公共市场、审核或收费机制。

## 入口与布局

从侧栏「项目」旁的 + 打开「添加项目」，默认浏览或输入已有目录，显示名称可自定义；也可以新建项目目录。再选择「普通项目」或「元Agent」用途后打开。类型只在添加项目时选择；已添加项目沿用原类型，项目列表仅用于进入项目。各项目保留会话、草稿、能力源码和最近访问位置；已有对话的紧凑顶部继续保持两行。目录与名称规则见 [添加项目](project-opening.md)。

元Agent 概览提供「开发中」和「个人资源库」两个管理视图。开发中展示能力项目、草稿版本、源码、结构校验、测试快照及发布记录；开发与试用都进入正常会话，不新增计划、工具、执行记录等任务标签。

预置 Package、Skill 和扩展三个草稿。新建能力项目可选择类型、名称和稳定资源 ID。源码编辑只修改原型内存，项目文件入口只读预览；开发会话的「变更」展示草稿源码前后内容。

## 生命周期

| 阶段 | 条件和行为 |
| --- | --- |
| 草稿 | 编写源码，保存后增加 revision，并使当前校验失效 |
| 结构校验 | 检查文件、清单/元数据、已声明工具和试用场景；失败不能创建测试快照 |
| 可测试 | 固定当前版本、revision 和源码，创建独立测试会话 |
| 发布个人版本 | 当前 revision 已通过结构检查并具备测试快照；版本不可重复发布 |
| 获取与使用 | 发布物进入现有目录，其他项目明确下载到节点、安装并启用 |
| 继续迭代 | 创建下一草稿版本；旧发布物、旧测试快照和已安装版本保持不变 |

每个测试会话固定源码快照。后续开发编辑不会改变测试文件预览。测试记录关联资源 ID、版本、revision、会话和追踪；修改源码后旧测试记录保留，但不能为新 revision 的发布提供通过依据。

## 三类产物

- **Skill**：SKILL.md 与参考/试用资料；发布后成为个人技能目录中的版本，需要单独获取和会话启用。
- **Package**：使用原型现有 JSON 设计包格式，组合技能、已知工具声明和提示词。发布后沿用节点获取与会话版本绑定。
- **扩展**：设计清单、源码入口和测试场景。原型使用明确标记的扩展设计格式和 Rust 源码示例，没有宣称它是 rpi 原生安装格式。

同一个个人 Skill 在本会话、同一个个人扩展在节点的模拟启用状态中，一次启用一个版本。历史版本保留，可以在安装就绪后明确切回。Package 继续使用现有“一份资源在会话中绑定一个版本”的规则。

个人资源库属于用户，各项目可复用。发布时复制源码、关联测试快照和版本元数据，不自动将产物安装到任何节点或改变会话能力。下载目标仍是 PC 执行节点；手机本地导出文件不代表节点已就绪。

## 元Agent 自身的配置

能力开发会话绑定「元Agent 开发助手」Package，包含开发约定与现有基础工具声明。原型将其明确作为预先下载、安装的开发模板；新产物仍遵守下载前置。以后可通过元Agent 编写和迭代这个开发 Package，再由使用项目明确选择新版本。

## 当前验证边界

结构检查在浏览器本地执行，不是模型行为评测或原生构建。测试会话可以继续输入试用问题，但响应仍来自原有流式模拟器；追踪记录明确标记本地快照结构检查，不构造真实模型耗时、Token 或扩展执行结果。发布只创建内存中的设计版本，不向服务器或仓库推送内容。刷新页面后恢复初始演示数据。

## 框架对象与职责

| 层 | 职责 |
| --- | --- |
| work-core | ProjectProfile（kind 为 project / capability）、CapabilityProject、DraftRevision、TestSnapshot、PersonalRelease、ResourceIdentity 与状态约束 |
| PC Agent 宿主 | 真实读取/写入源码、结构校验、构建和受控测试实例；分别记录开发回合与测试回合 |
| rpi-web / work-server | 项目、草稿、快照、产物和个人目录接口；节点获取任务、鉴权和事件恢复 |
| Dioxus UI | 切换项目、源码/变更、测试会话、追踪、个人版本与获取状态 |

发布接口应提交预期 revision、源码摘要和测试快照 ID，并由服务端核对，避免用旧结果发布新源码。测试绑定的是不可变 DraftRevision，正式会话绑定的是已安装 PersonalRelease；两者使用不同的资源引用类型。
