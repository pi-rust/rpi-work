# 会话资源与可下载 Package · v0.6

> 当前扩展实现：会话配置新增 Extensions，保存固定版本的 **desired Agent pins**；UI 可见性属于设备偏好，不是 Agent 开关。节点安装/应用与动态 UI 尚未接入。详见 [Agent / UI 扩展边界](../architecture/extensions.md)；下文安装流程仍是设计目标。

> 截图与运行报告为本地产物，不随Git分发；文中路径用于定位本地文件。保留规则与复验入口见 [测试产物说明](../guides/testing-artifacts.md)。

2026-10-24。Skills、Tools、提示词作为**会话配置**，入口位于对话内容上方的紧凑工具栏。输入框继续保留 Skills 选择，用于给某一条消息指定技能。

Package 是有名字、稳定 ID 和版本的资源组合，可以包含一个或多个 Skills、工具声明、会话指令和消息模板，也可以只包含其中一种。安装目录属于执行节点；启用哪些包、绑定哪个版本以及单项开关属于会话。

## 1. 界面位置

顶部仅保留导航与工具栏两行（共 96px，不含原型演示条）。标题并入导航栏；工具栏左侧为「对话 / 变更」，右侧「会话配置 · 包数量」打开统一资源面板，在面板中查看完整 Package 名称、版本和 Skills、Tools、提示词。宽屏额外显示能力数量快捷入口，手机只保留统一入口，不横向堆放 Package。数量表示当前目录，不表示模型已经使用。

状态菜单保留状态、项目、分支、创建时间及流式演示、分支会话等操作，按需查看。移动端继续通过顶部标题切换会话，避免重复的大标题和独立信息行挤占对话。

| 入口 | 内容 | 对会话的影响 |
| --- | --- | --- |
| 管理 Package | 已安装版本、来源、包含的资源、当前会话绑定 | 明确启用、停用或切换版本 |
| Skills | 会话可用目录、单项开关、来源与载入状态 | 影响后续可发现/可指定目录 |
| Tools | 可用工具、来源 Package、节点能力和权限范围 | 选择后续工具目录；不代替执行授权 |
| 提示词 | Package 会话指令、可手动套用的模板、本会话补充指令 | 指令作用于后续请求；模板先进入草稿 |
| 输入框 Skills | 选择本会话可用的某个 Skill | 只指定下一条消息，发送前仍是草稿引用 |

对话内继续保留技能全文载入证据、工具调用参数/输出、Ask、计划与结算记录。顶部负责配置，对话负责呈现本轮发生了什么；任务标签仍只有「对话 / 变更」。右侧不再重复放一份 Skills 配置。

侧栏的 Packages 和「技能库」是资源发现与管理入口。它们不替代会话顶部的当前有效配置。没有启用的包即使已经安装，也不能直接在输入框中指定它的技能。

## 2. 下载、安装与启用

生命周期分开表示：

`可获取 → 已下载 → 已校验 / 已安装到节点 → 本会话启用 → 本轮读取或调用`

- 下载不自动安装，安装不自动给任何会话增加能力。
- 扩展和独立 Skills 同样需要先下载到执行节点，再安装与启用，详见 [资源下载前置](resource-acquisition.md)。初始已启用资源是预先获取的示例。
- 同一包可以并存多个已安装版本，一个会话一次绑定一个明确版本。
- 安装更新后，现有会话继续使用旧版本，用户明确切换后才更新绑定。
- 运行中或等待 Ask 回答时暂不更改配置。后续可扩展为待应用配置，在宿主认可的轮次边界生效。
- 停用资源不删除历史记录，也不能撤回已经进入模型上下文的指令。
- 本轮发起时保存配置快照：包 ID/版本、工具集合、技能集合、会话指令及 revision。查看旧消息时不能套用今天的新配置。

手机上的「下载」需要区分两个目标：保存一个可分享的文件到手机，和让电脑/服务器安装一个资源包。默认的「安装到执行节点」应明确显示目标节点；不能把手机本地文件存在当成节点安装成功。

原型现在分为「下载到执行节点（模拟）」与「导出 JSON」两个动作。导出或导入 JSON 不会解锁节点安装；节点下载完成后才能安装，安装完成后再明确绑定会话。

当前原型实际可导出 JSON 设计包，并从用户主动选择的 JSON 文件重新导入。文件包含技能与提示词正文以及工具声明。没有远程下载请求、原生插件或真实节点安装；「模拟安装到节点」只改变页面样例状态。刷新后资源库和会话绑定重置，已经下载的文件由浏览器保存。

## 3. Package 组成与格式提案

产品层建议采用 `PackageId / Version / ResourceId`，显示名称可以改名、重复，资源身份保持稳定。资源引用应携带所属包和版本，不能只用技能名称定位。

可分发包的目标结构示意：

```text
package.json
skills/<skill-name>/SKILL.md
prompts/<template-name>.md
instructions/<instruction-name>.md
tools/<tool-name>.json
artifacts/<platform>/...       # 可选的原生工具实现
```

元数据至少包含：稳定 ID、名称、版本、作者、说明、来源、宿主兼容范围、资源清单、依赖和内容摘要。涉及原生实现时还要携带平台、架构、ABI/宿主兼容性和 artifact 校验值。工具声明本身不会产生工具实现；需要宿主内置工具、MCP 连接或扩展提供对应能力。

HTML 原型使用单个可携带文件，便于验证下载和导入，不解析 ZIP 或加载插件：

```json
{
  "schemaVersion": 1,
  "kind": "rpi-work-design-package",
  "id": "team.mobile-review",
  "name": "Mobile Review",
  "version": "0.3.0",
  "author": "Local Team",
  "description": "手机体验审阅资源包",
  "resources": {
    "skills": [{
      "id": "mobile-audit",
      "name": "mobile-audit",
      "description": "审阅手机交互",
      "content": "---\nname: mobile-audit\ndescription: Review mobile interaction.\n---\n\n# Mobile audit\n\nReview layout and touch targets."
    }],
    "tools": ["read", "grep"],
    "prompts": [{
      "id": "mobile",
      "name": "手机体验审阅",
      "kind": "template",
      "content": "请检查手机布局、触控目标与软键盘遮挡。"
    }]
  }
}
```

`kind` 明确标记为设计包，不能直接交给现有 `rpi install`。导出不包含用户草稿、附件、本会话补充指令、API Key 或聊天记录。导入按这个受限格式检查，不会执行包中的指令或工具声明；现阶段仅接受目录内已知工具。

同一 ID/版本且内容一致的文件可以重新导入，复用资源库记录；内容不同则要求新版本号，不能覆盖旧版本。原型比较规范化的清单与资源正文，正式安装仍需使用发布物内容摘要和校验机制。

## 4. 提示词与资源解析

提示词分为两类，不能混用：

1. `instruction`：供后续轮次组装的会话指令。界面可查看原文、包版本和单项开关。
2. `template`：手动操作的消息模板。套用时追加到现有草稿，保留未发送内容，不自动发送或当作已经进入上下文。

本会话补充指令单独保存，不写回共享 Package。原型快照记录启用的包指令与补充指令；真实宿主还需要返回最终组装的来源清单/指纹，避免把“配置了”误显示成“本轮已注入”。已进入上下文的旧指令是否需要重建会话或压缩，不能只靠开关假装撤销。

真实资源解析继续遵守宿主已有的优先级和冲突诊断。包内 ID 使用命名空间，避免两个下载包互相覆盖；同名技能、模板或工具的冲突应展示胜出来源及原因，不静默取最后安装的版本。原型为导入资源添加包版本命名空间，手动选择显示来源；完整宿主冲突解析尚未实现。

工具有效集合还要与节点可提供能力、用户授权和项目策略求交集。包声明了 browser 而节点没有实现时，显示「节点未提供」，不能勾选后就宣称可运行。

## 5. 与相邻仓库的边界

本轮读取了 `rpi-package/catalog/packages.json`、仓库 README 和 `pi-rust/crates/rpi-cli/src/resource_dirs.rs`：

- 当前资源仓库已有 extension 目录、名称/版本、来源和预构建 manifest；已有 `rpi install` 路径与原生安装流程可作为执行节点基础。
- 宿主已支持从项目、用户、package 资源目录发现 Skills 与提示词，并有来源优先级/冲突处理。
- 2026-10-24 基线新增确认：`rpi package link/list/update/unlink` 和项目 registry 已有实现，应该优先复用；它还不是本稿的多版本会话绑定。实际目录顺序包含“显式配置 → 项目 package → 常规项目目录”，不能只按抽象的项目/全局标签判断胜出来源。详见 [功能审阅](../archive/upstream-functional-review.md)。
- 这些不等于已经具备本稿的复合 Package schema、会话版本绑定、下载任务 API 或 Web 端统一资源管理。不能把本稿 JSON 宣称为上游已经支持的包格式。

框架分工提案：

| 层 | 新增职责 |
| --- | --- |
| 节点资源管理 | 包获取、校验、安装、已安装版本与资源目录，适配现有原生扩展安装机制 |
| rpi-web 协议 | 暴露目录、安装任务、资源能力和会话绑定；返回实际应用结果与 revision |
| work-core | `PackageManifest / InstalledPackage / SessionResourceBinding / EffectiveResources / RunResourceSnapshot` |
| Dioxus UI | 会话顶部资源条、资源配置面板、Package 详情与下载/安装进度、每轮配置快照 |

后续协议需要支持配置 revision 校验和多端竞争处理。手机和桌面同时修改时，服务端返回实际胜出的版本或冲突，不能客户端各自显示“保存成功”。同一个已安装包不应全局可变覆盖；运行中的会话与历史轮次继续引用各自固定版本。

原型中“禁用工具后不再出现对应流式演示工具卡”只是模拟器按会话快照选择示例事件，并没有向真实宿主执行 `set_active_tools`。
