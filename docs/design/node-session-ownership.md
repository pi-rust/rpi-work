# 节点、客户端与会话归属

本文说明当前节点/会话归属与尚未完成的产品边界。分层迁移和 Android 补验已完成，分批过程见[历史记录](../archive/node-session-migration.md)；新增代码遵循[开发规范](../guides/development-standards.md)。源码状态与已安装应用、真机验收分别判断。

## 1. 归属模型

- **节点是工作空间与会话的权威归属方。** 一个节点维护一份逻辑上的项目、会话目录、历史、运行状态与会话元数据，不按 Web、桌面、手机分别建一套。
- **客户端是节点的访问入口，不是另一份会话库。** 一个客户端可以连接多个节点；多个客户端也可以连接同一个节点。
- 同一节点、同一会话、同一授权范围内，各端读取同一份权威数据；列表、历史与运行状态的缓存需要更新与重连校准，而不是各端独立维护后再“合并同步”。
- “一份会话”指统一的数据来源与生命周期，不要求所有会话塞进同一个物理文件，也不代表一个节点只能有一个会话。
- 桌面本机工作空间也必须作为一个明确的节点建模。桌面可以承担节点宿主与客户端两个角色，但不能因客户端类型不同而隐式产生另一份会话目录。
- 同一台电脑可以显式运行多个独立节点；若数据独立，它们就是不同节点，不能仅因项目目录相同或运行在同一电脑而称为同一个节点。

```text
客户端 A（桌面） ─┬─ 节点 1 ─ 项目 / 会话 / 运行状态（节点 1 的权威数据）
                  └─ 节点 2 ─ 项目 / 会话 / 运行状态（节点 2 的权威数据）
客户端 B（Web） ──┬─ 节点 1（默认当前节点）
                  └─ 节点 2（用户主动连接）
客户端 C（移动） ─┬─ 节点 1（外部节点）
                  └─ 节点 2（其他外部节点，均受认证与共享边界约束）
```

### 1.1 客户端地位与默认节点（产品约定）

**Web 与桌面是平级客户端，都可以连接其他节点，但默认使用当前节点；移动客户端只连接其他节点，不托管本机节点。**

| 客户端 | 默认节点 | 是否可连接其他节点 | 本机节点托管 |
| --- | --- | --- | --- |
| 桌面 | 当前桌面托管的本机节点 | 可以，用户主动切换，也可返回当前节点 | 可以，桌面承担 owner 角色 |
| Web | 提供当前 Web 入口的节点 | 可以，与桌面同级；hosted 模式不取消此能力 | 浏览器自身不另建 owner |
| 移动客户端 | 无可直接使用的本机节点，须先连接并认证外部节点 | 只能使用外部节点，可主动更换目标 | 不托管，不把手机 localhost 当桌面节点 |

“默认当前节点”是启动时的默认操作上下文，不是永久锁定。Web 使用节点 A 提供的入口时默认操作 A，用户可以主动连接节点 B，再切回 A；不必将 Web 改成独立部署才能操作 B。桌面同理。这里的当前节点不是浏览器所在设备的 localhost，也不要求 Web 跟随桌面窗口当前选中的会话。

“移动客户端的其他节点”指移动设备之外的桌面或服务器节点，包含局域网和公网，并非只指云端。手机浏览器仍是 Web 客户端，遵循 Web 的入口与节点选择规则；屏幕宽度只影响布局，不能把 Web 改成只能外连的原生移动客户端。

默认选择、节点切换与身份认证是三个概念：宿主登录只向该宿主提交凭据；进入后主动切换节点须使用目标节点自己的授权。固定初始登录目标不能被扩大成“Web 只能使用宿主”。本节是产品设计约定，不表示现有所有入口和测试均已符合。

## 2. 节点身份与连接地址分离

- 节点身份回答“是哪一份工作空间”，连接地址回答“从哪里访问”。HTTP、代理、RPC 是访问路径，不应各自成为会话所有者。
- 同一个节点可以有本机 RPC、回环 HTTP、局域网或 HTTPS 代理等不同入口；只有明确映射到同一个权威工作空间时，才可视为同一个节点。
- 不根据端口、主机名、项目路径或服务名称自动认定两个入口是同一个节点。
- `rpi-work://local` 只在当前设备上下文有意义，不是跨设备全局节点 ID。当前连接地址只是客户端状态的隔离 key，不是稳定全局 `node_id`；同一节点经回环、代理或不同域名访问的多入口识别仍未实现。源码新增持久化桌面 `node-id` 和 health `nodeId`；客户端尚未据此统一不同地址的状态 key。
- 会话操作至少按 `(节点身份, 会话 ID)` 隔离；项目、草稿、事件游标与连接凭据也必须有明确节点作用域，不能跨节点复用。

## 3. 多节点客户端

- 区分客户端的“节点连接集合”和当前视图的“操作上下文”；切换节点不迁移、复制或删除会话。
- Web 与桌面均应提供主动连接其他节点及返回当前节点的路径；这不以 Web 是否为 hosted 部署为条件。移动客户端只有外部节点选择，不提供本机工作空间。固定宿主的初始认证表单不能永久屏蔽工作台中的节点切换。
- 一个客户端具备连接多个节点的模型，不把“保存多个最近地址”当作多节点连接已经完成。并行连接的调度与 UI 表现仍未实现。
- 当前项目、会话和执行位置必须明确归属于某一节点；不能把另一节点的响应、会话 ID 或工具调用发送到当前节点。
- 节点切换、重连及迟到响应必须按节点与连接代数隔离，保留其他节点的草稿与状态。切换只改变客户端视图/连接，不停止原节点 owner 或其正在进行的执行；只有退出桌面 UI 时才 shutdown 该桌面拥有的 embedded node，外部 HTTP 节点不随 UI 退出。
- 主题、侧栏宽度、展开状态、当前选择等属于端的 UI 偏好，不要求各端完全一致。当前本机侧栏的项目隐藏/归档仍属于端偏好，不据此删除或隐藏其他端的节点数据。

## 4. 权限与共享边界

- **能连到节点，不自动等于能访问全部项目、全部会话或执行全部操作。** 后续需要区分身份认证、资源可见性、会话操作权及工具执行审批。
- 客户端或其承载的本机节点是否允许其他端访问/接续，需要显式的共享策略；安装客户端、打开项目或拥有访问地址都不等于授权共享。
- 资源权限的最终校验必须在节点侧，不能只靠客户端隐藏菜单。不同授权范围可看到不同会话子集，这不等于节点存在多份会话库。
- 已有宿主控制的共享总开关并持久化；首次没有偏好时开启共享、默认 `0.0.0.0:13031`，显式关闭或损坏偏好均保持关闭。仅本机访问可显式回环监听；没有改变防火墙、通配 Host 或跨源授权。不新增邀请、配对审批、角色、ACL、多用户或逐设备授权；HTTP 保留密码和精确 Host/Origin。
- 现有共享密码认证不代表上述细粒度权限已实现。细粒度权限与共享策略仍需另行设计。

## 5. 当前实现与剩余边界

1. 桌面本机 RPC 与内嵌 `work-server` HTTP/SSE 持有同一 `Arc<LocalWorkspace>`；adapter 不再创建 owner、Service 或 registry。独立 standalone HTTP 仍是不同节点，旧副本不自动合并或迁移。
2. 桌面保留显式远程选择与历史恢复；`task desktop` 默认明确选择 `rpi-work://local`，不再把连接 standalone HTTP 当作桌面共享。
3. `task dev` 启动桌面 owner 与 Web；`14180` 将 API 及精确宿主声明同源代理到桌面 `13031`，默认自动进入该owner而非要求手动连接。直接启动 dev-web 也默认桌面13031和hosted策略。`task node` 才是独立 `13030` 节点；独立Web入口须显式使用standalone策略。不能同时运行第二个桌面抢占同一数据锁。
4. 项目/会话目录在窗口可见时按 3 秒刷新，focus/visible 补刷，按节点与连接 epoch 隔离；这是目录校准，不是文件复制或历史全量合并。
5. 桌面退出先 drain HTTP，再 shutdown 同一 workspace 的 children，最后释放 executor 和数据锁。HTTP 断流及客户端切换不停止 owner。
6. 桌面首次默认开启共享，保存关闭选择或偏好不可读/损坏时保持关闭；开关控制真实 HTTP/SSE 访问，关闭不停止本机运行。开启后本机页才显示地址分享、密码和独立的 Android App 一次性扫码授权入口；普通分享不授予权限，专用授权码是 120 秒单次 bearer 委托。可达地址与网络监听需明确配置；可在远程视图独立控制本机共享，仍无设备审批、设备权限列表或 ACL。
7. 默认 Web 的初始入口自动读取当前宿主 owner 的项目／会话，有效 Cookie 可直接进入；宿主声明失败不得静默改用其他节点。认证后可主动通过目标节点自己的 Web 入口切换，并手动返回原入口；目标独立认证，返回提示不选择节点、不授予权限。当前适配是页面导航，目标须提供 hosted 声明和 Web assets／同源代理，不支持任意 API-only 节点的浏览器跨源直连，也不是同页面多节点同时在线。已用隔离真实双 owner 的直接托管／代理、1440／390／320px 明暗展示、独立密码及认证失效恢复复验，见[报告](../../artifacts/web-node-navigation/REPORT.md)。手机浏览器走 Web 认证，Android 原生 App 仍使用自己的外部节点授权流程；未新增跨端选中项或草稿同步协议。
8. 同 owner 由隔离测试比较相同宿主 PID、会话 ID、元数据及事件序号证明；不能通过两个服务共写 JSON 或只读到相同目录来替代。
9. `work-host` 提供 GUI／无头共用生命周期；`work-cli serve` 与 `work-ui --headless` 不另建数据库。CLI 默认通过认证 HTTP 连接现有节点13031，typed 操作/订阅不拥有执行进程；原生 RPC/ACP 直连仅为显式诊断。桌面 `--connect` 或显式远程环境地址是纯客户端，不创建本机 owner、猜测端口身份或在连接失败时回退创建 owner。当前只有前台宿主和协作退出，系统服务安装/后台化仍未提供；范围及限制见[无头指南](../guides/headless-node.md)。

## 6. 验收约束（非原生 GUI 已验收声明）

- 两个端连接同一节点：创建、改名、归档和历史更新落在同一份节点数据中，另一端更新后得到一致结果。
- 一个端连接多个节点：操作、草稿、事件与凭据互不串用；相同会话 ID 在不同节点也不会冲突。
- Web／桌面平级：Web由A提供时默认进入A，主动连接B后可读写获授权的B会话，再返回A；默认入口失败不能自动跳B。宿主登录目标仍固定A，A的密码、Cookie和QR票据不得作为B的凭据。不得仅验证“hosted不能切换目标”便宣称满足此设计。
- 移动客户端：未连接外部节点时显示连接／授权入口，不生成本机工作空间；更换外部节点后数据和凭据隔离，不能fallback到手机localhost。
- 同一节点通过不同入口访问：稳定身份与多入口识别是后续目标，当前地址隔离 key 不能保证自动识别；不能据此宣称已经验收。
- 断线重连：从节点重新校准状态，不重复发送 prompt 或重放有副作用的操作。
- 权限/共享功能另行验收，不把本设计中的边界描述算作实现证据。

## 7. 会话应用入口现状

依赖方向为 **客户端 → Node 应用服务 → runtime**，本地调用不必绕行 HTTP：

- `work-core::api` 定义共享 DTO、typed `NodeApi`、`SessionAccess`、`SessionConfiguration` 和纯状态/事件投影，不持有执行宿主。应用 future 与事件端口不强制 `Send`。
- `work-node::workspace::LocalWorkspace` 是唯一 owner，持有 extcore Service、RPC/ACP 执行与会话绑定。`work-client::LocalWorkspace` 仅包装同一 Arc；`work-server` 接收该 owner，不另建 Manager 或运行状态。
- `WorkspaceClient` 与 `WorkClient` 转接会话、配置、执行、队列、对话和观测等 typed 方法。主工作台不按 native handle 是否存在选择执行路径；`AgentClient` / `prepare_agent_session` 保留为兼容和显式协议入口，不能用来新增 UI 旁路。
- 操作能力来自绑定会话的精确观察；未知/失败不回退全局能力或本机执行。`SessionAccess` 决定执行命令、快照限量和对话回复；`SessionConfiguration` 提供配置面命令和协商选项。它们不是授权或已加载资源证明。
- 本地保持 subscribe-before-snapshot，远端按 snapshot cursor 订阅；消息身份合并、快照恢复与客户端投影仍归 client。ACP snapshot 只恢复当前有效的 pending permissions，typed 回答由 node 核对 binding、generation 和 outstanding request。
- 保留 ACK/settlement、配置 deadline/权威回读/未知结果锁、草稿与附件确认、同地址重连 epoch、LocalSet 和退出顺序。详细不可破坏项统一维护在开发规范，不再逐批重复。

## 8. 验证状态与尚未验收范围

已完成迁移的自动化验证以及 ARM64/x86_64 client、mobile UI 的 NDK 交叉编译检查见[历史验证记录](../archive/node-session-migration.md)。这不是每次源码变化后自动更新的成绩单；复验命令见[测试产物说明](../guides/testing-artifacts.md)和[构建指南](../guides/ci-builds.md)。

以下仍不构成已完成能力：

- 客户端按稳定 node ID 合并同一节点的多地址身份，以及同时在线的多节点调度；当前缓存/凭据仍按地址隔离。
- 逐设备授权、角色/项目/会话 ACL；当前共享密码和一次性 Android 授权不是细粒度权限。
- Package/Skills 的精确选择、实际加载与 applied 观察契约，见[资源验证](../reviews/rpi-session-resource-validation.md)及[接口提案](session-resource-contract.md)。
- 原生 GUI、完整 APK 构建/签名、安装升级、真机和真实 Agent 的后续验收；编译和隔离 fixture 不能替代这些验证，也不代表已安装应用已更新。
