# 节点 Provider 管理

入口：**设置 → 供应商**。桌面、浏览器、移动客户端共用同一管理页；操作的是当前已认证节点，而非浏览器或手机本机的配置。不要求先选择项目、创建会话或启动控制宿主。

## 支持的操作

- 查看节点保存的 Provider 定义、模型、配置凭据是否存在、独立凭据类型和来源。
- 新增、编辑、删除自定义 Provider 定义；配置 Base URL、显示名称和模型行。
- 协议：`anthropic-messages`、`openai-completions`、`openai-responses`。
- 模型元数据：ID、名称、推理标记、上下文窗口、最大输出 token 数。
- 独立新增、替换和清除 API Key；**添加独立凭据**可只给内置供应商的准确原生 ID 保存密钥，不必创建或覆盖模型定义。
- 分别清除 `models.json` 的 `apiKey` 来源与 `auth.json` 的保存记录。
- 显式释放空闲原生宿主，让后续新宿主读取配置；不强停活动会话。

这里的目录是**保存文件中的记录**，不是完整的内置供应商清单，不枚举环境变量、命令行参数或内置运行时的所有默认值，也不表示某供应商已通过远端认证。会话的实际可用模型和选择仍由现有会话模型选择器及节点运行时报告。

## 推荐流程

### 自定义兼容接口

1. 点击「添加供应商」，填写唯一 ID、协议和 HTTP(S) Base URL。
2. 填写需要覆盖或新增的模型及 token 元数据，点击「仅保存定义」。
3. 等待「已权威回读」；然后在该记录中点击「保存独立密钥」。
4. 如已有宿主，等待其空闲后显式释放；后续宿主读取新配置。
5. 在会话模型选择器确认运行时实际报告的 Provider/模型，必要时选择模型。

### 只配置内置供应商密钥

1. 点击「添加独立凭据」，填写运行时准确的 Provider ID（不是显示名称）。
2. 输入密钥并保存；更改目标 ID 会立即清空密钥。
3. 此操作只写 `auth.json`，不创建 `models.json` 定义，也不在线校验 ID 是否受当前运行时支持。
4. 已有保存凭据不能从新增入口静默覆盖，须从对应记录确认替换。

### 删除与清理

- 「删除自定义配置」移除整个 `models.json` 定义，**包含该定义中的配置凭据**，但保留 `auth.json` 记录；凭据记录继续显示，可再独立清除。
- 「清除配置凭据」只移除定义中的 `apiKey` 字段，不清除自定义 headers、独立保存记录或环境变量。
- 「清除已存 API Key/OAuth」只删除 `auth.json` 对应记录，不删除模型定义。
- 删除配置不卸载内置供应商，也不能保证该供应商被禁用：环境变量、命令行、内置默认值等仍可能提供回退来源。
- 清除 OAuth 本地记录**不撤销远端授权**。OAuth 登录和授权撤销不由此表单执行；必要时在原生节点或供应商授权管理处处理。

## 保存、生效和验证是不同状态

页面仅在成功回执后再次读取节点，并核对 revision 和目标字段一致，才显示保存确认。凭据只能核对记录类型/来源存在，**不能回读密钥内容，也不能证明刚输入的值、远端认证或模型请求成功**。

保存文件不等于运行中的宿主热重载。当前原生契约没有通用 Provider 热重载接口：

- 已有活动宿主保持其配置，不自动切换、不强行终止会话。
- 「释放空闲原生宿主」复用既有资源释放接口；返回释放与阻塞数量，不承诺所有会话都已换用新配置。
- 新宿主读取保存文件；实际模型可用性和选择以运行时为准。
- 修改或删除当前使用的 Provider 不会自动修改会话选择。后续启动/恢复是否可用仍取决于运行时配置与凭据。

## 节点文件及兼容性

适配现有原生 `models.json` 与 `auth.json`，不另建 Provider 注册中心。目录在 owner 创建时捕获：有效的绝对 `RPI_CODING_AGENT_DIR`，否则原生 home 下 `.rpi/agent`。无效配置不会偷偷回退写入另一个目录。节点数据目录不自动等于原生 agent root。

定义和独立凭据是两个操作、两个文件：每次只原子替换一个文件，**不是跨文件事务**。定义更新保留未知字段、JSON 对象顺序及相同模型 ID 的高级配置。保存会重新排版并去除 JSON 注释，不保证原始文本格式不变。

已有供应商和模型 ID 不直接改名。移除模型并保存会删除该模型及高级字段；更换为新 ID 不继承旧 ID 的高级字段。未映射的协议、缺少必要元数据、类型不兼容的已知字段等显示诊断并禁止表单覆盖；需在节点端编辑，或明确删除后重新创建。重复 JSON key 会使读取/写入失败关闭，不采用 last-key-wins。

这不是任意原生版本、协议或高级字段的完整编辑器；保留固定上游依赖，不升级或替换已安装的原生运行时。本轮没有验证安装的真实原生宿主加载此配置或进行真实模型调用。

## 并发、故障与安全

- opaque revision 覆盖两个文件的原始字节，并绑定 owner 随机盐。外部写入或 owner 重启后，旧 revision 不能覆盖新状态。
- 同 owner gate、生命周期 lease、跨 owner 配置锁和落盘前复查共同保护应用写入；不宣称能与忽略锁的外部程序构成强事务。
- 使用私有暂存文件、同步后替换；Unix 新文件为 `0600`。Windows 依赖目录继承的 ACL；不会修改系统安全策略。原生凭据仍按其原有明文格式保存，应保护 agent root。
- 拒绝链接/reparse/special 文件、超限文件、非法路径和非法定义。Base URL 不允许内嵌凭据、query、fragment 或空白；保存过程不访问该 URL。
- 新密钥按原生语法转义为**字面量**，不执行 `!command`、不展开 `$ENV`；此管理 API 不调用凭据解析器。
- 请求、目录和错误反馈不回显已有密钥/header。页面不把密钥写入 localStorage；提交、取消、切换连接/目标或卸载时清空输入。
- 超时不代表节点写入已取消。结果不确定时锁住后续写入，须「刷新并核对」，不自动重试。非秘密定义草稿可显式恢复；密钥草稿不恢复。
- 继续使用现有节点密码、精确 Host/Origin、写入标记、sharing/admission 边界。远程传递凭据应使用可信 HTTPS 或安全隧道，不把节点管理员访问交给不信任用户。

## 接口及实现

- `GET /api/v1/providers`：脱敏保存目录与 opaque revision。
- `POST /api/v1/providers`：严格 typed mutation，要求 `expectedRevision`。
- `POST /api/v1/providers/release-idle-hosts`：空对象请求，释放既有空闲资源。
- core：`crates/work-core/src/api/providers.rs`。
- 唯一 owner：`crates/work-node/src/workspace/providers.rs`。
- typed 门面：`crates/work-client/src/providers.rs`。
- 共享页面：`apps/work-ui/src/features/settings/providers.rs`。

验证范围、命令和平台限制见 [Provider 验证记录](../../artifacts/providers/README.md)。
