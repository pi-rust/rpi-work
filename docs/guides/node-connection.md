# 节点连接交互

## 设计约束与当前实现

已确认的目标模型为：**一个节点维护一份权威会话数据，一个端可以连接多个节点，多个端可以接续同一节点的会话**。桌面本机工作空间也是节点；传输方式、端口和客户端类型不应各自成为会话库边界。权限与是否允许其他端接续/共享需单独设计，本轮不新增共享 ACL。详见[节点、客户端与会话归属](../design/node-session-ownership.md)。

源码中的桌面现在同时承担 owner 与客户端：本机 RPC、内嵌认证 HTTP/WebSocket 访问同一个 `LocalWorkspace`。另行启动的 standalone HTTP 仍是其他节点，既有迁移副本不自动合并。首次没有共享偏好时默认开启局域网共享；已保存的关闭选择和损坏／不可读偏好不会被启动逻辑覆盖。关闭会断开外部 WebSocket 和登录但不停止本机任务，也不影响桌面访问其他节点；Web/手机无权修改宿主共享开关。右侧执行环境及会话导航以文字和电脑/云图标区分本机与远程（不把局域网称为云端）。配置与运行边界见[桌面 HTTP 入口](desktop-http.md)。

## 当前入口

认证方式取决于**入口来源和客户端类型**，不是屏幕宽度：

| 入口 | 进入工作台之前 | 默认节点 |
| --- | --- | --- |
| 宿主提供的 Web（含手机浏览器） | 先用宿主密码登录；有效 Cookie 可恢复 | 页面同源的宿主，不被节点历史覆盖 |
| 独立部署的 Web | 选择/输入节点，再连接并完成该节点认证 | 用户选择的节点 |
| Android 原生 App | 扫描短期一次性授权码，核对地址后点“授权连接”；不输入密码 | 此次扫码授权的节点，不从历史恢复 |

Web 与桌面是平级客户端：默认使用当前节点，也都可以主动连接其他节点。宿主 Web 默认使用提供入口的节点，必要时认证后自动加载其项目、session和任务状态，不要求为默认节点另填地址或点击连接；这不意味着只能操作宿主，也不要求切成standalone部署后才允许换节点。移动客户端不托管本机节点，只能连接其他设备的节点；手机浏览器仍遵循Web规则。完整产品约定见[节点与会话归属 §1.1](../design/node-session-ownership.md)。

初始宿主门禁由 `/.well-known/rpi-work-entry` 的明确声明识别；配置assets或有效Web代理端口均可声明。默认开发代理转发此声明，上游404按配置缺失返回502而不是自动转向旧节点；异常响应不能绕过登录。显式standalone静态入口对该路径返回真实404，不能回退到HTML。默认开发Web与API分别为14180／桌面13031。初始认证仍固定当前宿主，之后主动切换须单独认证目标节点；不得将这一安全规则误作Web永久禁止切换的限制。

### 宿主 Web 切换节点

登录后进入 **设置 → 执行节点／连接我的电脑 → 连接其他电脑**，输入目标节点的 Web 入口并点 **连接节点**。各宽度使用同一连接屏幕，打开地址表单不会立即离开当前工作空间，也不会采集目标密码。

- Web 通过顶层页面导航进入目标节点自己的同源 Web 页面，由目标执行宿主发现及独立认证；不从原页面跨源调用目标 API，不增加任意目标代理，也不放宽 Host/Origin/CORS。原生桌面和 Android 继续使用各自的直接节点传输。
- 目标须提供支持 `/.well-known/rpi-work-entry` hosted 声明的 Web assets 或同源 Web 代理。仅 API 的节点要先配置 Web 入口；从本入口切换到缺少声明的静态 standalone 页面会明确失败，不以目标页面的旧历史改连第三个节点。直接打开显式 standalone 部署仍保留原连接流程。
- 目标节点认证后显示 **返回入口节点** 及其地址。返回提示只包含公开 HTTP(S) origin，经校验后存于当前 origin 的 `sessionStorage`；跨页面传递使用片段，不含密码、Cookie或授权票据。提示不代表身份或授权，不自动跳转，不覆盖初始认证目标。刷新目标页仍默认目标节点；返回时重新验证入口节点，Cookie 有效则自动进入。
- 当前节点认证失效时，连接页提供 **重新登录当前节点**，重新进入该节点自己的门禁，不会落入隐藏密码框的死路。退出 B 不会主动退出 A，也不按尚未提交的地址草稿选择退出目标。
- 页面导航不停止节点任务，但不是在一个页面内维持多个在线连接，也不承诺自动保存未提交输入；离开前请自行保留。浏览器 Cookie 按 host 而非端口隔离：同 host 多端口可能自动附带多个 Cookie，节点使用独立 nodeId 的 Cookie 名和认证存储区分授权；不要把端口当作凭据保密边界。

隔离双 owner 的直接托管／真实代理、三种宽度、独立密码、同 sessionId 数据隔离、返回及认证失效恢复证据见 [Web 节点导航报告](../../artifacts/web-node-navigation/REPORT.md)。这不是线上部署或 Android 真机验收。

独立 Web 的手机布局提供相机、相册和手动地址；桌面及独立 Web 的手动连接/地址扫码只输入**节点密码**，不提供连接 Token 输入。密码位于原 Token 位置，可先填写再点击连接，一次完成认证与工作空间加载；未填写时仍可在密码提示后登录，同一表单不重复显示密码框。桌面本机 owner 与共享就绪后，在工作台启动时自动尝试一次 **App 授权二维码**，不用先进入设置。设置页可显式重开；普通 Web 地址分享仍是单独入口，要求手机可达的同源 Web/代理，不能是 localhost。App 授权只需要认证 API，不依赖 Web assets。填写分享地址不会扩大监听。

### Android 一次性扫码授权

宿主桌面或已认证 Web 的 **手机 App 扫码授权** 是单独入口，不等同于普通“分享当前连接”。授权码使用 `rpi-work-node-auth` v1，包含目标地址、节点标识、短期随机票据及到期时间；不含长期密码或 Cookie。120 秒有效，只能兑换一次。App 先核对目标节点，再兑换普通认证会话，成功后自动加载项目/session。二维码生成窗口有倒计时，到期隐藏；关闭窗口不等于撤回已签发票据，关闭共享可使未兑换票据和已兑换登录一并失效。

**任何拿到尚未过期授权码的人都可能访问整个工作空间，只向可信手机展示。** 票据不进入 URL、日志、连接历史或持久存储；App 重开或“扫码更换电脑”必须重新授权。建议使用 HTTPS；普通局域网 HTTP 不提供传输加密，仅应在可信网络使用。后台会清除尚未兑换的授权，但已进入的工作台不因短暂切后台自动登出。相机不可用时可用相册本地识码；没有密码/历史地址作为原生 App 的替代登录入口。该机制不是设备审批、逐设备权限或 ACL。

`task desktop` 默认选择本机 owner；`task dev` 启动桌面与 Web（14180 同源代理到桌面 13031），不要再额外启动桌面。`task node` 是明确独立的 standalone 节点。显式远程设置仍可用于连接其他节点，之后用“使用这台电脑”返回本机。

桌面按 `RPI_WORK_RPI_BIN`、应用同目录、PATH、RPI Work 自动安装目录和 Cargo 用户目录（通常为 `~/.cargo/bin`，Windows 为 `%USERPROFILE%\.cargo\bin`）查找 rpi，模型凭据仍在 rpi 中。`RPI_WORK_DATA_DIR` 控制数据目录并持有独占锁；同一 owner 的 HTTP 默认监听 `0.0.0.0:13031`，保留密码和 Host/Origin 校验，不自动修改防火墙。显式设置 `127.0.0.1` 时仍仅使用回环，不能无代理生成局域网二维码。切换视图不停止任务；只有退出桌面才依次清理 listener、workspace children 和锁。源码不会给当前运行的旧二进制热添加入口，重新启动时间由用户自行安排。

Android始终使用手机模式；原生桌面始终使用电脑模式。Web结合移动设备标识与窄屏断点选择入口，手机横屏仍保持手机模式；从窄屏恢复到桌面布局会关闭相机并释放轨道。

普通地址分享仍使用 `rpi-work-node-address` 版本化协议，不包含密码，也不授予访问权限；Android 原生 App 要使用上面的专用授权码。回环、通配地址、凭据与未知协议版本仍被拒绝。原生BarcodeDetector不可用时，以随应用分发的jsQR本地解码；相册识别不上传图片。

相机只在点击“打开相机”后申请权限，不请求麦克风。Android 由 Wry 处理运行时授权，拒绝后可重试或改用相册；后摄约束不被设备支持时降级到普通视频请求，权限拒绝不会自动再次申请。相机初始化最多等待 30 秒，超时后可重试；关闭相机、离开页面或应用切到后台会释放视频轨道，迟到的授权结果也会释放。连续识码复用画布并限制频率，避免每屏幕帧都运行 jsQR。

独立 Web 的手机布局识别到有效相机/相册地址二维码后先清空旧节点密码，再展示地址供用户核对，绝不自动连接；请在本次确认区输入目标节点密码。密码仅为内存草稿，绑定输入时的规范化节点地址；编辑地址、切换扫码/手动输入或重新识码会清空，提交即清空，不向其他节点复用，也不写入连接历史或二维码。Web 相机需要浏览器安全上下文（通常为 HTTPS；手机上的普通局域网 HTTP 页面不可用），不可用时仍可相册本地识码或手动输入地址。Android 系统相册选择不需要额外的广泛存储权限；相机硬件为可选，不能因无相机而阻止安装和相册扫码。

正式WASM复验：构建后运行 `node tests/e2e/verify-device-flow.cjs`，覆盖桌面连接、分享二维码、手机识别后确认、真实二维码图片解码、延迟相机权限关闭和移动布局。`node tests/e2e/verify-mobile-scanner.cjs` 进一步覆盖后摄约束降级、拒绝恢复、启动超时与迟到轨道释放、真实二维码视频帧的 jsQR 解码、旧密码清空以及扫码确认前输入密码后的一步连接。`node tests/e2e/verify-ui-auth-scope.cjs` 覆盖连接前密码、错误重试、地址隔离、无重复密码框与 Cookie 重连。相机权限/硬件使用测试流，不能代替 Android 真机摄像头与系统权限弹窗验证。旧手机连接设计稿和原型截图属于历史设计，以本说明为准。

## 分享当前连接

Web 的 **设置 → 执行节点 → 分享当前连接**、手机浏览器的 **连接我的电脑 → 我的电脑 → 分享当前连接** 可分享已在线的节点；原生桌面查看远程节点时也使用同一入口。弹窗默认来自当前已连接节点，不使用尚未提交的地址草稿。支持扫码、**复制地址**和**复制连接信息**（版本化 JSON）。分享不含密码、Token 或 Cookie，接收方仍需输入节点密码；这不授予权限，也不会修改宿主共享开关。

若当前地址是 localhost/回环，需要在弹窗填写同一节点对方可达的局域网或 HTTPS 同源 Web/代理入口，不能把 API 端口误作 Web 入口。修改地址后即时更新，也可点击 **重新生成**；无效地址不生成二维码、连接数据或启用重新生成/复制。填写不会切换当前连接、修改监听或自动开放防火墙。剪贴板不可用时可手动复制。切换或重新连接节点会关闭旧弹窗，再打开时恢复当前节点，旧异步复制结果不覆盖新节点提示。

桌面启动时默认提供的是 **Android App 一次性授权码**，不是不能用于 App 登录的普通地址码。地址优先显式 public URL，否则使用已配置同源代理端口或默认局域网认证 API；无需 Web assets。没有有效地址、监听失败或共享已关闭时不生成伪可用二维码。只自动尝试一次；到期、关闭、失败、重连和设置页重挂载都不续签，需手动重新生成。详见[自动生成条件](desktop-http.md#自动生成局域网二维码)。Web/手机只分享其当前连接，不检测别的电脑网卡。

专项复验：`node tests/e2e/verify-connection-share.cjs` 覆盖 Web/手机入口、当前连接与草稿隔离、二维码真实解码、两种复制与失败回退、无凭据、切换/重连清理、无效地址、390/320 明暗布局以及零节点变更。剪贴板为模拟接口，手机为浏览器布局测试，不代表实体设备或系统分享面板验收。

## 连接生命周期

连接探测与密码登录最终进入同一条加载流程：节点认证 → 协议能力 → 会话列表 → 项目列表。未填写密码时先做健康检查并读取认证状态；已填写密码则直接向所选节点登录，成功后加载工作空间，无须再次点击连接。任何一步失败都显示具体失败阶段，不把项目加载失败当成已就绪。整个尝试最多等待15秒，可以重试；切换节点或再次连接时取消前一次尝试，并以连接代数丢弃旧结果。编辑地址不会修改正在使用的节点，输入无效地址也不会清空当前工作空间。

成功连接后在本设备保存最多8个远程节点地址，最近使用的排在最前；另用历史字段 `selected` 保存最后成功选择（可为本机），兼容只有 `recent` 的旧记录。原生桌面 `--connect HTTP(S)_ORIGIN` 优先于显式 `RPI_WORK_NODE_URL`，远程显式启动是纯客户端，不创建本机 owner；显式 `rpi-work://local` 仍启动本机 owner。没有显式选择时，默认 GUI 保留本机 owner，并恢复 `selected`，缺失时兼容 `recent`，无记录时访问本机。启动地址校验失败在创建节点前报错，连接失败/超时在共享连接界面报错，不会无声 fallback 到本机或其他节点。无头节点的启动、停止及 CLI 认证见[无头指南](headless-node.md)。独立 Web 重开可恢复历史节点，认证过期时再次要求密码；宿主 Web 始终先验证同源宿主，Android 原生 App 始终重新扫码，二者都不按其他历史节点自动连接。未认证、失败和超时的地址不会成为成功选择，桌面私有节点不加入远程 `recent`。记录不含密码或认证 Cookie；原生桌面保存在本机配置目录的 `rpi-work/nodes.json`，Web和Android使用本地WebView存储 `rpi-work-nodes-v1`。存储不可用时提示保存失败，连接仍可使用。

桌面设置可从“最近连接”切换节点或清除地址记录；清除不终止当前连接，但下次重开不再按该记录自动连接。独立 Web 的手机布局保留扫码、手动输入和当前电脑的重新连接入口；手动编辑草稿不会改变当前连接，地址校验失败也不会清空已有工作空间。Android 原生 App 仅提供“扫码更换电脑”，不提供密码、手动地址或历史节点切换作为认证捷径。手机不会恢复桌面回环地址。相册选中同一张二维码可重复识别。

普通分享二维码仅传递地址；专用 App 授权二维码是有时限的单次 bearer 委托。未实现设备配对审批、设备列表或逐设备权限。Web 和 Android 不启动节点进程。

连接后，项目/会话目录在窗口可见时每 3 秒刷新一次，focus 或恢复 visible 时立即刷新（已有请求在途时随后补刷），隐藏时暂停。左侧 **项目标题旁的“刷新会话”按钮** 可立即从当前节点拉取最新会话及项目目录，桌面、Web 与手机共用；刷新中显示状态并禁用重复点击。若已有自动请求在途，会等它结束后补拉一轮，避免用点击前的旧快照冒充最新数据。失败保留最后成功目录并提示重试；成功提示“已拉取最新会话”。

手动与自动刷新共用同一队列、超时和隔离逻辑；按节点与连接 epoch 丢弃过期结果，同时检查本端请求期间的目录变更，避免覆盖并发改名、归档等操作。刷新不会重新连接、切换选中会话或清空输入草稿；切换节点会清除旧刷新状态。此机制用于目录校准，不是全量消息历史同步，也不自动重发 prompt。

新增复验：`node tests/e2e/verify-node-lifecycle.cjs`，覆盖真实浏览器Cookie登录、密码错误、自动重连、过期认证、地址校验、过期响应、项目加载失败、超时重试、清除记录与窄屏布局。与扫码脚本一起运行；服务端使用隔离HTTP测试节点，不触碰用户正在运行的节点。

项目文件夹选择器先读取节点返回的项目根目录，再以根目录下的相对路径查询子目录；界面展示和表单回填保持绝对路径。上级目录在项目根目录处禁用，超出根目录的路径会明确提示，不向 API 发送盘符或绝对路径。`node tests/e2e/verify-project-auth.cjs` 覆盖认证、进入/返回目录、完整路径回填和过期认证恢复；测试节点按实际协议拒绝绝对路径。
